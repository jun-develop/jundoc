Jungo

A Go REST API skeleton (Gin + Uber Fx) organised in layers: handler, service, repository. Clone it and run a few commands to get an API with authentication (opaque tokens), users, roles and permissions, migrations, a feature generator and a CLI console. You add your own code one feature at a time.

Bộ khung REST API viết bằng Go (Gin + Uber Fx), chia tầng: handler, service, repository. Clone về và chạy vài lệnh là có API kèm authentication (opaque token), user, role và permission, migration, công cụ sinh feature và console CLI. Bạn thêm code của mình theo từng feature.

Step 1Bước 1 make app-init
Asks for app name, DB name/user/password, ports and a CI provider — press Enter to keep each default. Creates .env with auth secrets, writes a release CI workflow (GitHub or GitLab, unless you pick none), warns if migrate, psql or sqlc is missing, and deletes .git and starts a fresh repository (no commits). Run it once, on a fresh clone.
Hỏi tên app, tên/user/mật khẩu DB, port và nhà cung cấp CI — cứ nhấn Enter để giữ giá trị mặc định. Tạo file .env kèm auth secret, ghi một workflow CI cho release (GitHub hoặc GitLab, trừ khi chọn none), cảnh báo nếu thiếu migrate, psql hay sqlc, và xóa .git rồi tạo repository mới (chưa có commit). Chỉ chạy một lần, trên bản clone mới.
Step 2Bước 2 make app-dev-bg
Docker Desktop must be open. Builds and starts API + PostgreSQL in the background; it returns once PostgreSQL is healthy. The API is not ready yet.
Docker Desktop phải đang mở. Build và chạy API + PostgreSQL ở chế độ nền; lệnh kết thúc khi PostgreSQL đã sẵn sàng. API thì chưa sẵn sàng.
Step 3Bước 3 make migrate-up
Creates tables, permissions, SQL functions and loads demo users (admin, manager, member, user). Run it now: the API refuses to start until the permissions it uses are in the database.
Tạo bảng, permission, SQL function và nạp user demo (admin, manager, member, user). Chạy ngay bây giờ: API không chịu khởi động cho tới khi các permission nó dùng có trong database.
Step 4 · waitBước 4 · chờ make app-logs
Watch the logs until you see server: starting, then press Ctrl+C (it only closes the log view). The API listens on localhost:$API_SERVER_PORT — the port you chose in app-init (default 8080); every example in these docs uses it.
Theo dõi log đến khi thấy dòng server: starting, rồi nhấn Ctrl+C (chỉ thoát màn hình log). API lắng nghe ở localhost:$API_SERVER_PORT — port bạn chọn ở app-init (mặc định 8080); mọi ví dụ trong tài liệu đều dùng biến này.
Important:Quan trọng: the first start is slow. The container downloads every Go module and compiles the whole app before it can answer; until server: starting appears, curl hangs or gets "connection refused". Keep watching make app-logs instead of restarting. Later starts are fast, because the modules and build cache stay in Docker volumes. If the app exits (database not migrated yet), Air starts it again 3 seconds later. lần chạy đầu rất chậm. Container tải toàn bộ Go module và biên dịch cả app trước khi trả lời được; trước khi thấy server: starting, curl sẽ treo hoặc báo "connection refused". Cứ xem make app-logs, đừng tắt đi chạy lại. Các lần sau nhanh vì module và build cache được giữ trong Docker volume. Nếu app thoát (database chưa migrate), Air chạy lại sau 3 giây.

Đường dẫn không tồn tại trả 404 (api_not_found), đúng đường dẫn nhưng sai method trả 405 (method_not_allowed). Tùy chọn của từng middleware: junkit middleware.

A second entrypoint, cmd/console, for one-off jobs — migrations, cleanups, backfills, reports. It builds the same config, DB and services as the API (CoreModules), but no HTTP server.
