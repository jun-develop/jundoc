Jungo · Audit log

Audit log

A record of who changed what and when. The services write it themselves with auditlog.Recorder, inside the transaction that makes the change, so the change and its entry commit together or not at all. Out of the box it covers changes to users and roles made through the API. Entries are kept 30 days.

Bản ghi cho biết ai đã thay đổi gì và lúc nào. Các service tự ghi bằng auditlog.Recorder, trong chính transaction thực hiện thay đổi, nên thay đổi và bản ghi audit cùng commit hoặc cùng không. Mặc định có sẵn cho các thay đổi user và role đi qua API. Bản ghi được giữ 30 ngày.

ConceptsKhái niệm

The technical logs (storage/logs) say what the server did. The audit log says what happened to the data: one audit entry per recorded change, in the audit_logs table.

Log kỹ thuật (storage/logs) cho biết server đã làm gì. Audit log cho biết dữ liệu đã thay đổi ra sao: mỗi thay đổi được ghi là một bản ghi audit, trong bảng audit_logs.

2

How a change is recordedMột thay đổi được ghi thế nào

The service makes the change and calls Record in the same WithTransaction. If recording fails, the change rolls back.

Service thực hiện thay đổi và gọi Record trong cùng một WithTransaction. Nếu ghi audit lỗi, thay đổi bị rollback.

internal/common/auditlog/auditlog.go
// Entry is one change to record. Who acted and the trace ID are taken from the context.
type Entry struct {
	Action     string
	EntityType string
	EntityID   string
	Before     map[string]any
	After      map[string]any
}

// Recorder writes entries to the audit log.
type Recorder interface {
	Record(ctx context.Context, e Entry) error
}

2. AuditService.RecordTakes the actor from actor.From(ctx) (the logged-in user's UUID) and the trace ID from logger.GetTraceID(ctx), and turns Before and After into changes: each key of After (of Before for a delete) whose value differs, as {"before": …, "after": …}. Values compare as JSON, so a field sent with its current value is left out. When Before and After are both set and no value differs, nothing is recorded; an entry with neither (change_password) is recorded with empty changes.Lấy actor từ actor.From(ctx) (UUID của user đang đăng nhập) và trace ID từ logger.GetTraceID(ctx), rồi biến Before và After thành changes: mỗi key của After (của Before với delete) có giá trị khác nhau, dạng {"before": …, "after": …}. Khi cả Before và After đều có mà không giá trị nào khác, không có gì được ghi; bản ghi không có cả hai (change_password) vẫn được ghi với changes rỗng.

The audit feature is optionalFeature audit là tùy chọn

audit.Module provides the Recorder under the name audit; provideAuditRecorder (internal/app/fx.go) hands it to the features. Remove audit.Module and the features get auditlog.Nop, a Recorder that records nothing, with no other change.

audit.Module cung cấp Recorder với tên audit; provideAuditRecorder (internal/app/fx.go) đưa nó cho các feature. Bỏ audit.Module thì các feature nhận auditlog.Nop, một Recorder không ghi gì, mà không cần sửa gì khác.

Recording in your featureGhi audit trong feature của bạn

make feature does not add auditing. Take auditlog.Recorder in the service's params and call it in the transaction that makes the change:

make feature không thêm audit. Nhận auditlog.Recorder trong params của service và gọi nó trong transaction thực hiện thay đổi:

internal/features/order/service/order_service.go
err := s.repo.WithTransaction(ctx, func(ctx context.Context) error {
	order, err := s.repo.GetForUpdate(ctx, id) // locked: the values this change replaces
	if err != nil {
		return err
	}

	if err := s.repo.UpdateName(ctx, id, name); err != nil {
		return err
	}

	return s.audit.Record(ctx, auditlog.Entry{
		Action: auditlog.ActionUpdate, EntityType: "orders", EntityID: id.String(),
		Before: map[string]any{"name": order.Name},
		After:  map[string]any{"name": name},
	})
})
1

Never put a secret in Before or After: no password, hash or token. Nothing masks it later.

Không bao giờ đưa bí mật vào Before hay After: không mật khẩu, hash hay token. Sau này không có gì che nó đi.

2

Before and After: Before is nil for a create, After for a delete. Read the old values in the transaction, after locking the row, so they are the ones the change replaces. For a partial update, auditlog.Changes(input) builds After from the non-nil pointer fields of a struct, keyed in snake_case (stringx.ToSnake); a field tagged audit:"-" is skipped. Record values as the API shows them: a status by name ("active", not 1), an empty list as [], not null.

Before và After: Before là nil với create, After là nil với delete. Đọc giá trị cũ trong transaction, sau khi đã khóa dòng, để đó đúng là giá trị bị thay thế. Với cập nhật một phần, auditlog.Changes(input) tạo After từ các field con trỏ khác nil của một struct, key dạng snake_case (stringx.ToSnake); field có tag audit:"-" bị bỏ qua. Ghi giá trị như API hiển thị: status theo tên ("active", không phải 1), danh sách rỗng là [], không phải null.

3

Pass the transaction's ctx, not context.Background(): otherwise the entry is written outside the transaction and loses the actor and trace ID.

Truyền ctx của transaction, không phải context.Background(): nếu không, bản ghi được ghi ngoài transaction và mất actor cùng trace ID.

EndpointEndpoint

Read only. Needs Authorization: Bearer <access_token> and audit_logs:read (granted to super_admin). Without a token → 401 Authentication token is invalid or expired (other token errors: Authentication); without the permission → 403 You do not have permission to perform this action.

Chỉ đọc. Cần Authorization: Bearer <access_token> và audit_logs:read (cấp cho super_admin). Thiếu token → 401 Authentication token is invalid or expired (các lỗi token khác: Xác thực); thiếu permission → 403 You do not have permission to perform this action.

GET/api/v1/audit-logsaudit_logs:read

The history of one entity, or what one user did. Every filter is optional and they combine; with none, every entry. Newest first (created_at, then id) unless sort_order=asc, paginated. Each entry carries its actor and an entity_label, joined at read time, so a client needs no other read to show it.

Lịch sử của một entity, hoặc những gì một user đã làm. Mọi bộ lọc đều tùy chọn và kết hợp được với nhau; không có bộ lọc nào thì trả mọi bản ghi. Mới nhất trước (theo created_at, rồi id) trừ khi sort_order=asc, có phân trang. Mỗi bản ghi kèm actor và entity_label, được join lúc đọc, nên client không cần gọi thêm để hiển thị.

RetentionThời gian lưu

Entries are kept 30 days (domain.Retention in internal/features/audit/domain/audit.go; change it there). audit:cleanup-logs deletes older ones; schedule it daily so each run deletes about one day's rows.

Bản ghi được giữ 30 ngày (domain.Retention trong internal/features/audit/domain/audit.go; muốn đổi thì sửa ở đó). audit:cleanup-logs xóa các bản ghi cũ hơn; hãy lên lịch chạy hằng ngày để mỗi lần chỉ xóa khoảng một ngày dữ liệu.

terminal
$ make console CMD="audit:cleanup-logs"
 ✅ Deleted 312 expired audit entries
6

LimitsGiới hạn

1

It records what the code records. A change made outside the services (SQL by hand, a migration, a service method that does not call Record) leaves no entry.

Chỉ ghi những gì code ghi. Thay đổi ngoài service (SQL tay, migration, method service không gọi Record) không để lại bản ghi nào.

2

Entries are ordinary rows. Anyone who can write to the database can change or delete them, including the app's own database login (DB_USER, a superuser in the dev stack).

Bản ghi chỉ là dòng dữ liệu bình thường. Ai ghi được vào database đều sửa hoặc xóa được chúng, kể cả login database của chính app (DB_USER, là superuser trong stack dev).

3

No undo. Entries are not replayed: nothing restores a row from them; fix bad data through the API (that fix is recorded too) or by hand.

Không có undo. Không có gì phát lại các bản ghi để khôi phục một dòng; hãy sửa dữ liệu sai qua API (lần sửa đó cũng được ghi lại) hoặc bằng tay.
