Four words to knowBốn khái niệm cốt lõi

Everything else is built on these.

Mọi thứ khác đều dựa trên bốn khái niệm này.

1

Session

One login on one device. Has an ID (family_uuid) and always holds exactly one access + one refresh token. Logging out ends the session.

Đại diện cho một phiên đăng nhập trên một thiết bị. Có mã phiên (family_uuid) và luôn sở hữu đúng một access token + một refresh token hợp lệ. Khi đăng xuất, session sẽ bị hủy.

2

Access token

The "key card" sent on every API call: Authorization: Bearer …. Short-lived: 15 minutes.

"Thẻ ra vào" gửi kèm mọi request yêu cầu xác thực: Authorization: Bearer …. Thời gian sống ngắn: 15 phút.

3

Refresh token

Used only to get a new pair when the access token expires. Lives 30 days, works once.

Chỉ dùng duy nhất khi access token hết hạn để lấy cặp token mới. Thời gian sống 30 ngày, cơ chế dùng 1 lần (xoay vòng token).

4

Device

Recognised by the X-Device-ID header (or IP + User-Agent). Logging in again from the same device reuses its session instead of opening a new one.

Nhận diện thiết bị qua header X-Device-ID (hoặc IP + User-Agent). Nếu đăng nhập lại trên cùng thiết bị, hệ thống tái sử dụng session cũ thay vì mở session mới.

Why two tokens? A stolen access token is useless within 15 minutes. The long-lived refresh token is sent rarely (only to /auth/refresh) and can be used only once.

Vì sao cần hai token? Nếu access token bị lộ thì chỉ có giá trị tối đa 15 phút. Refresh token sống dài hơn nhưng chỉ gửi tới đúng endpoint /auth/refresh và bị vô hiệu ngay sau lần dùng đầu tiên.

POST/api/v1/auth/loginpubliccông khai

Checks email + password and returns a token pair. Same device already logged in → that session is rotated (its old tokens stop working) instead of creating a second one.

Kiểm tra email + mật khẩu và trả về cặp token. Nếu cùng thiết bị đã đăng nhập → session đó được xoay vòng (token cũ ngừng hoạt động) thay vì tạo session thứ hai.

4.3 · Refresh rotation & reuse detection4.3 · Xoay vòng refresh & phát hiện token bị dùng lại

Each refresh token works once. If an already-used refresh token comes back, the server can't tell a thief from a buggy client, so it ends the whole session.

Mỗi refresh token chỉ dùng được một lần. Nếu refresh token đã dùng bị gửi lại, server không phân biệt được kẻ trộm hay client lỗi, nên hủy cả session.

The whole exchange is one database call, the function f_auth_refresh_session: it locks the refresh token, checks it, retires the old pair and stores the new one. Two refreshes with the same token therefore run one after the other, and the second one is treated as reuse.

Cả lần đổi token chỉ là một lần gọi database, function f_auth_refresh_session: nó khóa refresh token, kiểm tra, hủy cặp cũ và lưu cặp mới. Vì vậy hai lần refresh với cùng một token sẽ chạy lần lượt, và lần thứ hai bị coi là dùng lại.

4.5 · Same device = same session4.5 · Cùng thiết bị = cùng session

When a user logs in, the database function f_auth_login_session looks for an active session of that user on the same device: same X-Device-ID, or — when no device ID is sent — same IP + User-Agent (an IPv6 address matches any address in its /64 block, since phones and laptops change their IPv6 address often). Found → its two tokens are replaced in place (rotated); the old ones stop working and now answer "Invalid token". Not found → a new session (2 rows) is created.
Khi user đăng nhập, function f_auth_login_session trong database tìm session đang hoạt động của user đó trên cùng thiết bị: cùng X-Device-ID, hoặc — khi không gửi device ID — cùng IP + User-Agent (địa chỉ IPv6 khớp với mọi địa chỉ trong cùng khối /64, vì điện thoại và laptop đổi địa chỉ IPv6 thường xuyên). Có → hai token của nó được thay tại chỗ (xoay vòng); token cũ ngừng hoạt động và giờ trả về "Invalid token". Không có → tạo session mới (2 dòng).
Why send X-Device-ID? Without it, a phone that changes Wi-Fi (new IP) looks like a new device → a second session appears in /auth/sessions. With it, the user sees one entry per real device.
Vì sao nên gửi X-Device-ID? Không có nó, điện thoại đổi Wi-Fi (IP mới) sẽ trông như thiết bị mới → thêm một session nữa trong /auth/sessions. Có nó, user thấy mỗi thiết bị thật đúng một dòng.

api.js
const API = "http://localhost:$API_SERVER_PORT/api/v1";
let refreshing = null; // one refresh at a time — two in parallel look like token theft

async function refresh() {
  const res = await fetch(`${API}/auth/refresh`, {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-Device-ID": store.deviceId },
    body: JSON.stringify({ refresh_token: store.refresh }),
  });
  if (!res.ok) { store.clear(); goToLogin(); throw new Error("session ended"); }
  const { data } = await res.json();
  store.save(data.access_token, data.refresh_token); // always replace BOTH
}

export async function api(path, init = {}) {
  const call = (token) => fetch(API + path, {
    ...init,
    headers: { ...init.headers, Authorization: `Bearer ${token}` },
  });
  const sent = store.access;
  let res = await call(sent);
  if (res.status === 401) {
    const { message } = await res.clone().json();
    if (message === "Token has expired" && store.access === sent) {
      refreshing ??= refresh().finally(() => (refreshing = null));
    }
    if (message === "Token has expired" || message === "Token has been revoked") {
      await refreshing; // wait for a refresh already running, if any
      if (store.access !== sent) res = await call(store.access); // retry once with the newest token
    }
  }
  return res;
}
