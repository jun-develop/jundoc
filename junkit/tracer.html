Add ?t_debug=<value> plus an X-Internal-Secret header to any URL and, instead of the normal response, get a report of that one request: every SQL query with its rows, your timed spans, notes, values and errors — HTML in a browser, JSON in a terminal.

What it doesNó làm gì

A Debugger rides on the request context. Every tracer call and every query through PgxWrapper appends an entry to it; at the end the middleware throws away the real response and renders the entries.

Đối tượng Debugger được gắn vào context của từng request. Mọi lệnh ghi log từ tracer và câu truy vấn SQL qua PgxWrapper sẽ tích lũy thành các entry. Khi kết thúc, middleware chặn nội dung response thông thường và xuất thẳng trang báo cáo debug trực quan.

middleware.TracerDebug thấy key = value và header secret, gắn tracer.New() vào context.

What the dashboard shows (top to bottom)Dashboard hiển thị gì (từ trên xuống)

  • DB card (only if there were queries): QUERIES, FAILED, DB TIME, % OF REQUEST, and one line per query that ran more than once: ⚠️ GetRole ran 10 times (…ms total), possible N+1.
  • Thẻ DB (chỉ khi có query): QUERIES, FAILED, DB TIME, % OF REQUEST, và một dòng cho mỗi query chạy hơn một lần: ⚠️ GetRole ran 10 times (…ms total), possible N+1.
  • ⏱ Timeline: a waterfall of every span (green) and SQL query (blue), positioned by start offset and width = duration / total.
  • ⏱ Timeline: biểu đồ thác nước của mọi span (xanh lá) và câu SQL (xanh dương), đặt theo thời điểm bắt đầu, độ rộng = thời lượng / tổng.
  • Entries in recorded order: 💬 comments, ⏱ spans, and cards for variables, warnings, errors (location + collapsible Stack Trace) and SQL (bound SQL, rows / result / row_count / rows_affected, red border and ✘ error + 📍 origin if it failed).
  • Các entry theo thứ tự ghi: 💬 comment, ⏱ span, và các thẻ cho variable, warning, error (vị trí + Stack Trace thu gọn được) và SQL (SQL đã gắn tham số, rows / result / row_count / rows_affected, viền đỏ và ✘ error + 📍 nơi gọi nếu lỗi).
  • Last entry: REQUEST & SERVER INFO — method, URL, client IP, headers (secrets masked), Go version, pid, goroutines.
  • Entry cuối: REQUEST & SERVER INFO — method, URL, IP client, header (đã che bí mật), phiên bản Go, pid, số goroutine.

Wire it upKết nối vào app

Two hooks: the middleware that switches the recorder on, and the DB wrapper that sees the SQL. tracer has no Options struct — the only settings are the middleware.TracerDebugOptions (query key / value, secret header / secret) passed to middleware.TracerDebug.

Hai điểm nối: middleware bật bộ ghi, và DB wrapper để thấy SQL. tracer không có struct Options — cấu hình duy nhất là middleware.TracerDebugOptions (query key / value, header secret / secret) truyền cho middleware.TracerDebug.

internal/database/primary/db.go
func options(cfg *config.Config) postgres.Options {
    return postgres.Options{
        Name: "primary",
        DSN:  cfg.DB.DSN(cfg.Timezone),
        // ...
        Decorate: func(inner postgres.DBTX) postgres.DBTX {
            return tracer.NewPgxWrapper(inner)
        },
    }
}
internal/router/router.go
debug := middleware.TracerDebugOptions{
    QueryKey:     cfg.TracerDebugKey,
    QueryValue:   cfg.TracerDebugValue,
    SecretHeader: "X-Internal-Secret",
    Secret:       cfg.Auth.InternalSecret,
}

p.Router.Use(
    middleware.TracerDebug(debug),
    middleware.Security(),
    // ... Trace, CORS, Gzip, Payload, AccessLog (SkipIf: debug.Matches), Limiter ...
    // a panic in a debug request becomes a "PANIC RECOVERED" error entry
    middleware.Recover(p.HTTPLogger, p.Notifier, p.Responder, middleware.RecoverOptions{Debug: debug}),
)
main.go
pool, err := pgxpool.New(ctx, dsn)
if err != nil {
    log.Fatal(err)
}

// Anything with Exec / Query / QueryRow works: *pgxpool.Pool, pgx.Tx, postgres.DBTX.
queries := sqlc.New(tracer.NewPgxWrapper(pool))

r := gin.New()
r.Use(middleware.TracerDebug(middleware.TracerDebugOptions{ // any empty field = off
    QueryKey:     "t_debug",
    QueryValue:   os.Getenv("TRACER_DEBUG_VALUE"),
    SecretHeader: "X-Internal-Secret",
    Secret:       os.Getenv("INTERNAL_SECRET"),
}))
r.GET("/users/:id", userHandler.Get) // handlers pass ctx down to queries

Use it in 30 secondsDùng ngay trong 30 giây

Instrument a service method, then call the endpoint with the debug key. Hover an explanation to light up its lines.

Instrument một method của service, rồi gọi endpoint kèm debug key. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

order_service.go
func (s *OrderService) Checkout(ctx context.Context, order Order) error {
    defer tracer.Span(ctx, "Checkout")()

    tracer.C(ctx, "starting checkout")
    tracer.V(ctx, "order", order)

    var err error
    tracer.Measure(ctx, "Charge payment provider", func() {
        err = s.payments.Charge(ctx, order.Total)
    })
    if err != nil {
        tracer.E(ctx, "charge failed", err)
        return err
    }

    if tracer.Enabled(ctx) {
        tracer.V(ctx, "cart snapshot", s.buildSnapshot(order))
    }

    tracer.Stop(ctx, "state before save", order)
    return s.repo.Save(ctx, order)
}

funcNewPgxWrapper ·
                PgxWrapper

            

              
func NewPgxWrapper(inner dbtx) *PgxWrapper

func (w *PgxWrapper) Exec(ctx context.Context, sql string, args ...any) (pgconn.CommandTag, error)
func (w *PgxWrapper) Query(ctx context.Context, sql string, args ...any) (pgx.Rows, error)
func (w *PgxWrapper) QueryRow(ctx context.Context, sql string, args ...any) pgx.Row


            

            
    
              
  • dbtx is unexported but is just Exec / Query / QueryRow with the pgx signatures
                — a pool, a pgx.Tx or postgres.DBTX fit.
    • 
              
  • dbtx không được export nhưng chỉ là Exec / Query / QueryRow theo chữ ký của pgx
                — pool, pgx.Tx hay postgres.DBTX đều dùng được.
    • 
              
  • Installed through postgres.Options.Decorate, it wraps the executor itself — the pool
                and every transaction — not sqlc, so hand-written SQL run through Executor(ctx) is
                captured too.
    • 
              
  • Được gắn qua postgres.Options.Decorate, nó bọc chính executor — pool và mọi
                transaction — chứ không bọc sqlc, nên SQL viết tay chạy qua Executor(ctx) cũng được ghi
                lại.
    • 
              
  • No Debugger → the inner call is returned unchanged (not even wrapped rows).
    • 
              
  • Nếu context không có Debugger → thực thi và trả nguyên kết quả gốc (không phát sinh overhead
                hay bọc rows).
    • 
              
  • Each query becomes one sql entry. Label = sqlc name from
                -- name: GetUser :one, else a guess from the first keyword (e.g. Select).
                Operation = the sqlc kind upper-cased (ONE, MANY, EXEC…).
    • 
              
  • Mỗi query thành một entry sql. Label = tên sqlc lấy từ
                -- name: GetUser :one, nếu không có thì đoán từ từ khoá đầu (vd. Select).
                Operation = loại của sqlc viết hoa (ONE, MANY, EXEC…).
    • 
              
  • Exec records rows_affected. Query records the scanned rows (max
                20) and the true row_count — once, when rows.Close() is called.
                QueryRow is run as a Query internally (to get column names) and records result at
                Scan; no row → pgx.ErrNoRows is recorded as an error.
    • 
              
  • Exec ghi rows_affected. Query ghi các dòng đã Scan (tối đa 20) và
                row_count thật — một lần, khi gọi rows.Close(). QueryRow bên trong chạy
                bằng Query (để có tên cột) và ghi result lúc Scan; không có dòng →
                pgx.ErrNoRows được ghi là lỗi.
    • 
              
  • []byte columns: valid JSON (e.g. jsonb) is shown as JSON, anything else as hex.
                Failed queries also get location / function of the app code that ran them
                (sqlc's *.sql.go skipped).
    • 
              
  • Cột []byte: JSON hợp lệ (vd. jsonb) hiện dạng JSON, còn lại hiện dạng hex.
                Query lỗi có thêm location / function của code app đã chạy nó (bỏ qua file
                *.sql.go của sqlc).
    •
