apidoc

API docs built from the code: the OpenAPI 3.0.3 document is generated from the request and response structs you already have, so field names and validation rules cannot drift, and is served as an interactive page with Scalar.

Tài liệu API sinh từ code: tài liệu OpenAPI 3.0.3 được sinh từ chính các struct request và response bạn đã có, nên tên field và luật kiểm tra không thể lệch, rồi hiển thị thành trang tương tác bằng Scalar.

What it doesNó làm gì

You describe each route in one line. Everything else is read from code that already exists.

Bạn mô tả mỗi route bằng một dòng. Mọi thứ còn lại được đọc từ code đã có sẵn.

Quick startDùng nhanh

A DTO you already have, one Route per endpoint, then build and serve. Hover an explanation to light up its lines.

Một DTO bạn đã có, mỗi endpoint một Route, rồi build và phục vụ. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

product_dto.go
type CreateProductRequest struct {
    Name  string `json:"name" binding:"required,min=2,max=100" example:"Coffee"`
    Price int64  `json:"price" binding:"required,min=0"`
    Kind  string `json:"kind" binding:"omitempty,oneof=food drink"`
}

var ErrProductExists = response.New(response.Conflict, "product_already_exists")
main.go
ops := []apidoc.Operation{{
    Route: apidoc.Route{
        ID:     "createProduct",
        Method: http.MethodPost, Path: "/api/v1/products",
        Summary:  "Create a product",
        Body:     CreateProductRequest{},
        Status:   http.StatusCreated,
        Response: ProductResponse{},
        Errors:   []*response.AppError{ErrProductExists},
    },
    Tag:      "products",
    Security: apidoc.Security{Bearer: true, Permissions: []string{"products:create"}},
}}

spec, err := apidoc.Spec(apidoc.Info{Title: "API", Version: "v1"}, ops)
if err != nil {
    return err
}
apidoc.Register(router, "/docs", "API docs", spec)

typeHeader · Security · Operation · Info
type Header struct {
    Name        string
    Description string
    Required    bool
}

type Security struct {
    Bearer       bool     // needs "Authorization: Bearer <token>"
    APIKeyHeader string   // needs this header holding a shared secret
    Permissions  []string // permission codes the caller must hold
}

type Operation struct {
    Route           // Path here is the full path
    Tag      string // the group the route is listed under
    Security Security
}

type Info struct {
    Title   string
    Version string
    Enums   []Enum // string types and the values they can hold
}

Bearer adds a bearerAuth scheme; APIKeyHeader adds an apiKey scheme named after the header. Neither adds an error response: list the 401 / 403 errors in the route's Errors. Permissions are listed at the top of the route's description and in an x-permissions extension.

Bearer thêm scheme bearerAuth; APIKeyHeader thêm scheme apiKey mang tên header. Cả hai không thêm response lỗi nào: hãy liệt kê lỗi 401 / 403 trong Errors của route. Permissions được liệt kê ở đầu phần mô tả của route và trong extension x-permissions.

funcEnumOf · Enum
func EnumOf[T ~string](values ...string) Enum

type Enum struct { /* unexported */ }

Gives a string type the values it can hold, for values known only at run time (a fixed set fits an enum tag). Each becomes a component schema named after the type, and every field of type T, []T or *T refers to it: apidoc.Info{Enums: []apidoc.Enum{apidoc.EnumOf[PermissionCode](codes...)}}.

Cho một kiểu string biết các giá trị nó có thể nhận, dành cho giá trị chỉ biết lúc chạy (tập cố định thì dùng tag enum). Mỗi enum thành một component schema mang tên kiểu, và mọi field kiểu T, []T hoặc *T trỏ tới nó: apidoc.Info{Enums: []apidoc.Enum{apidoc.EnumOf[PermissionCode](codes...)}}.

funcSpec
func Spec(info Info, ops []Operation) ([]byte, error)
  • Paths use Gin's syntax (/users/:uuid) and come out as /users/{uuid}.
  • Path dùng cú pháp Gin (/users/:uuid) và được đổi thành /users/{uuid}.
  • Every success response uses junkit's envelope: status, message, data, api_info.
  • Mọi response thành công dùng khung của junkit: status, message, data, api_info.
  • One error response per status of the route's Errors (plus 422 validation_error for a body or query), with code and reason limited to those errors. validation_error is a variant of its own, the only one that carries error (field → message, or one message for broken JSON). The Error component lists every code and reason the document uses.
  • Mỗi status trong Errors của route thành một response lỗi (thêm 422 validation_error khi có body hoặc query), với code và reason giới hạn đúng các lỗi đó. validation_error là một biến thể riêng, duy nhất có error (field → message, hoặc một message khi JSON hỏng). Component Error liệt kê mọi code và reason mà tài liệu dùng.
  • Fails when an operation has no ID, two operations share one, or an enum type's name is already taken (APIInfo, Pagination, Error or another enum).
  • Trả lỗi khi một operation không có ID, hai operation trùng ID, hoặc tên kiểu enum đã bị dùng (APIInfo, Pagination, Error hoặc một enum khác).
  • Sorts ops in place (by path, then GET, POST, PUT, PATCH, DELETE). Two operations with the same method and path: the later one wins, silently.
  • Sắp xếp ops tại chỗ (theo path, rồi GET, POST, PUT, PATCH, DELETE). Hai operation trùng method và path: cái sau thắng, không báo lỗi.
funcRegister
func Register(r gin.IRoutes, path, title string, spec []byte)

Serves the Scalar page at path and the document at path + "/openapi.json". Import the JSON into Postman or Insomnia, or generate a frontend client from it.

Phục vụ trang Scalar ở path và tài liệu ở path + "/openapi.json". Có thể import file JSON vào Postman, Insomnia, hoặc dùng để sinh client cho frontend.

Feature chỉ cần viết Docs(); router lo phần còn lại và không cho app khởi động khi thiếu docs.

3Errors are what you listLỗi là những gì bạn khai báoSpec cannot see which errors a handler returns. A route whose Errors misses one documents a reason enum the server breaks, and a generated client may reject the answer. Keep Errors next to the code that returns them.Spec không thấy được handler trả lỗi nào.
