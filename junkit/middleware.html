What is in the boxTrong package có gì

Ten middleware form the global chain; two (BearerAuth, RequireSecret) guard single route groups. Each one is a plain gin.HandlerFunc: code before c.Next() runs on the way in, code after it on the way out. Press ▶ to follow one request.

Mười middleware tạo thành chuỗi chung; hai cái (BearerAuth, RequireSecret) chỉ canh một route group. Mỗi cái là một gin.HandlerFunc bình thường: code trước c.Next() chạy lúc đi vào, code sau nó chạy lúc đi ra. Bấm ▶ để theo dõi một request.

How Jungo registers themJungo đăng ký chúng thế nào

There is no middleware.Module: you call the constructors where routes are registered. Jungo does it in two places — once globally, and per feature router for auth.

Không có middleware.Module: bạn gọi constructor ngay chỗ đăng ký route. Jungo làm ở hai nơi — một lần cho toàn bộ, và trong router của từng feature cho phần xác thực.

Global chain — internal/router/router.goChuỗi chung — internal/router/router.go

internal/router/router.go
func registerGlobalMiddlewares(p Params) {
    cfg := p.Config
    debug := middleware.TracerDebugOptions{
        QueryKey:     cfg.TracerDebugKey,
        QueryValue:   cfg.TracerDebugValue,
        SecretHeader: "X-Internal-Secret",
        Secret:       cfg.Auth.InternalSecret,
    }

    p.Router.Use(
        middleware.TracerDebug(debug),
        middleware.Security(),
        middleware.Trace(middleware.TraceOptions{
            Version:     cfg.Version,
            Commit:      cfg.Commit,
            Environment: cfg.Environment,
        }),
        middleware.CORS(middleware.CORSOptions{
            AllowOrigins:     cfg.CORS.AllowOrigins,
            AllowMethods:     cfg.CORS.AllowMethods,
            AllowHeaders:     cfg.CORS.AllowHeaders,
            AllowCredentials: cfg.CORS.AllowCredentials,
            MaxAge:           cfg.CORS.MaxAge,
        }),
        middleware.Gzip(middleware.GzipOptions{Level: gzip.BestSpeed}),
        middleware.Payload(middleware.PayloadOptions{
            MaxBodySize: cfg.Security.MaxRequestBodySize,
        }, p.Responder),
        middleware.AccessLog(p.HTTPLogger, middleware.AccessLogOptions{
            SkipIf: debug.Matches,
        }),
        middleware.Limiter(middleware.LimiterOptions{
            RequestsPerSecond: cfg.Limiter.RequestsPerSecond,
            Burst:             cfg.Limiter.Burst,
            NumShards:         cfg.Limiter.NumShards,
            CleanupInterval:   cfg.Limiter.CleanupInterval,
            ClientTTL:         cfg.Limiter.ClientTTL,
            LogTTL:            cfg.Limiter.LogTTL,
            IPWhitelist:       cfg.Limiter.IPWhitelist,
        }, p.LimiterLogger, p.Responder, p.Notifier),
        middleware.RoutePatterns(map[string]func(string) bool{
            "uuid": middleware.IsUUID,
            "id":   middleware.IsID,
            "slug": middleware.IsSlug,
        }, p.Responder),
        middleware.Recover(p.HTTPLogger, p.Notifier, p.Responder, middleware.RecoverOptions{Debug: debug}),
    )
}

Why each position matters (reasoned from the code — router.go itself has no comments on the order):

Vì sao mỗi vị trí quan trọng (suy ra từ code — bản thân router.go không có comment về thứ tự):

1TracerDebug — outermostIt swaps the response writer and request context before anything else runs, so every layer below records into the tracer, and its deferred render runs last, replacing whatever was written. It also catches tracer.Stop() breakpoints from anywhere below.Nó thay response writer và request context trước khi mọi thứ khác chạy, nên mọi lớp bên dưới đều ghi vào tracer, và hàm render (defer) chạy cuối cùng, thay thế mọi thứ đã được ghi. Nó cũng bắt breakpoint tracer.Stop() từ bất kỳ đâu bên dưới.
2Security — before anything can answerHeaders are set before c.Next(), so even early answers (204 preflight, 413, 429, 401, 500) carry them.Header được đặt trước c.Next(), nên cả những câu trả lời sớm (204 preflight, 413, 429, 401, 500) cũng có chúng.
3Trace — before any responder callresponder.Send reads trace ID, start time, version and env from the Gin context to fill api_info; AccessLog reads the trace ID too. Anything that answers before Trace gets no trace_id and no X-Trace-Id.responder.Send đọc trace ID, thời điểm bắt đầu, version và env từ Gin context để điền api_info; AccessLog cũng đọc trace ID. Cái gì trả lời trước Trace sẽ không có trace_id và không có X-Trace-Id.
4CORS — before body, limits and authPreflight OPTIONS is answered 204 before the body is read, before a rate-limit token is spent and before auth. And error answers from later layers (413/429/401/500) still carry Access-Control-Allow-Origin, so the browser lets the front-end read them.Preflight OPTIONS được trả 204 trước khi đọc body, trước khi tốn token rate limit và trước khi xác thực. Và lỗi từ các lớp sau (413/429/401/500) vẫn có Access-Control-Allow-Origin, nên trình duyệt cho front-end đọc được.
5Gzip — after CORS, around everything that writes a bodyPreflights (204, no body) are answered before it. Every body written later — 413, 429, 401, 500 and handler JSON — is compressed when the client sent Accept-Encoding: gzip. AccessLog sits inside it, so it still logs the plain body. BestSpeed: JSON compresses well even at the cheapest level.Preflight (204, không có body) được trả lời trước nó. Mọi body ghi sau đó — 413, 429, 401, 500 và JSON của handler — đều được nén khi client gửi Accept-Encoding: gzip. AccessLog nằm bên trong nó nên vẫn log body gốc. BestSpeed: JSON nén tốt ngay cả ở mức rẻ nhất.
6Payload — before AccessLog and handlersOversized bodies are cut off with 413 before any further work. It caches the parsed body so AccessLog can log request_payload and handlers can still bind it.Body quá lớn bị chặn với 413 trước khi làm gì thêm. Nó cache body đã parse để AccessLog ghi được request_payload và handler vẫn bind được.
7AccessLog — wraps Limiter, Recover, handlerIt logs after c.Next() returns, so it sees the final status — including 429 from Limiter and 500 from Recover. SkipIf keeps debug-dashboard requests out of the log.Nó ghi log sau khi c.Next() trả về, nên thấy status cuối cùng — kể cả 429 từ Limiter và 500 từ Recover. SkipIf loại các request dashboard debug khỏi log.
8Limiter — before the expensive partA rejected request gets 429 without touching handlers or the database, and the rejection is still access-logged.Request bị từ chối nhận 429 mà không chạm tới handler hay database, và việc từ chối vẫn được ghi access log.
9RoutePatterns — after Limiter, before authJunk URLs such as /users/abc still spend a rate-limit token, then get 404 before BearerAuth or the handler runs.URL rác như /users/abc vẫn tốn token rate limit, rồi nhận 404 trước khi BearerAuth hay handler chạy.
10Recover — innermostIt only catches panics from what runs after it (handlers, BearerAuth). Being innermost, its 500 still flows out through AccessLog, CORS, Trace and Security. On a debug request it hands the panic to the tracer instead, so TracerDebug can show it.Nó chỉ bắt panic từ những gì chạy sau nó (handler, BearerAuth). Vì nằm trong cùng, response 500 của nó vẫn đi ra qua AccessLog, CORS, Trace và Security. Với request debug, nó chuyển panic cho tracer để TracerDebug hiển thị.

Một main.go hoàn chỉnh Không dùng Fx (lược bỏ import và type Identity struct{ UserID string }; đã kiểm tra biên dịch được). Rê chuột vào giải thích để làm sáng các dòng tương ứng.

main.go
func main() {
    log := zap.NewExample()
    responder := response.NewResponder(response.Options{Language: i18n.LangEN}, i18n.NewTranslator())
    debug := middleware.TracerDebugOptions{QueryKey: "t_debug", QueryValue: "change-me",
        SecretHeader: "X-Internal-Secret", Secret: "change-me-secret"}

    r := gin.New()
    _ = r.SetTrustedProxies(nil) // ClientIP() = the TCP peer address
    r.Use(
        middleware.TracerDebug(debug),
        middleware.Security(),
        middleware.Trace(middleware.TraceOptions{Version: "v1.0.0", Environment: "development"}),
        middleware.CORS(middleware.CORSOptions{
            AllowOrigins: []string{"http://localhost:3000"},
            AllowMethods: []string{"GET", "POST", "OPTIONS"},
            AllowHeaders: []string{"Authorization", "Content-Type"},
            MaxAge:       600,
        }),
        middleware.Payload(middleware.PayloadOptions{MaxBodySize: 2 << 20}, responder),
        middleware.AccessLog(log, middleware.AccessLogOptions{}),
        middleware.Limiter(middleware.LimiterOptions{
            RequestsPerSecond: 10,
            Burst:             30,
            CleanupInterval:   time.Minute,
            ClientTTL:         3 * time.Minute,
            LogTTL:            30 * time.Second,
        }, log, responder, nil),
        middleware.Recover(log, nil, responder, middleware.RecoverOptions{Debug: debug}),
    )

    r.POST("/echo", func(c *gin.Context) {
        responder.SendWithData(c, http.StatusOK, "operation_successful", middleware.GetPayload(c))
    })

    authn := middleware.AuthenticatorFunc[*Identity](func(ctx context.Context, token string) (*Identity, error) {
        if token != "demo" {
            return nil, response.New(response.Unauthorized, "unauthorized_token")
        }
        return &Identity{UserID: "42"}, nil
    })
    me := r.Group("/me", middleware.BearerAuth(authn, responder, middleware.BearerAuthOptions{}))
    me.GET("", func(c *gin.Context) {
        responder.SendWithData(c, http.StatusOK, "operation_successful", security.MustGetIdentity[*Identity](c))
    })

    _ = r.Run(":8080")
}

Turns on the tracer dashboard for requests whose query has ?<QueryKey>=<QueryValue> and whose SecretHeader header equals Secret. Otherwise it just calls c.Next().

Bật dashboard tracer cho request có query ?<QueryKey>=<QueryValue> và header SecretHeader bằng Secret. Ngược lại chỉ gọi c.Next().

  • Matches(c) is that check (the secret is compared in constant time). Pass it as AccessLogOptions.SkipIf and the same options as RecoverOptions.Debug.
  • Matches(c) chính là phép kiểm tra đó (secret được so sánh constant-time). Truyền nó làm AccessLogOptions.SkipIf và truyền cùng options làm RecoverOptions.Debug.
  • Disabled when any field is empty.
  • Tắt khi có bất kỳ field nào rỗng.
  • When active: puts a fresh tracer into the request context and swaps c.Writer for one that discards the body the handler writes. The handler still runs for real (database writes happen).
  • Khi bật: đặt một tracer mới vào request context và thay c.Writer bằng writer bỏ đi body mà handler ghi. Handler vẫn chạy thật (ghi database vẫn xảy ra).
  • Afterwards it always answers 200 with Cache-Control: no-cache, no-store, must-revalidate, Pragma: no-cache, Expires: 0.
  • Sau đó luôn trả 200 kèm Cache-Control: no-cache, no-store, must-revalidate, Pragma: no-cache, Expires: 0.
  • Body: if the User-Agent contains curl, httpie or wget (case-insensitive) → application/json; charset=utf-8; otherwise → text/html; charset=utf-8 (the interactive dashboard).
  • Body: nếu User-Agent chứa curl, httpie hoặc wget (không phân biệt hoa thường) → application/json; charset=utf-8; ngược lại → text/html; charset=utf-8 (dashboard tương tác).
  • A tracer.BreakpointSignal panic (from tracer.Stop()) is caught and the dashboard notes "⏸ Stopped by tracer.Stop() after …". Any other panic is re-panicked.
  • Panic tracer.BreakpointSignal (từ tracer.Stop()) được bắt và dashboard ghi "⏸ Stopped by tracer.Stop() after …". Panic khác được panic lại.

funcTracetrace.go
func Trace(opts TraceOptions) gin.HandlerFunc
  • Reuses the incoming X-Trace-Id request header as-is, or generates uuid.NewString().
  • Dùng lại nguyên văn header request X-Trace-Id nếu có, không thì sinh uuid.NewString().
  • Puts it in the request context with logger.WithTraceID (read it back with logger.GetTraceID(ctx)) and sets the response header X-Trace-Id.
  • Đưa nó vào request context bằng logger.WithTraceID (đọc lại bằng logger.GetTraceID(ctx)) và đặt header response X-Trace-Id.
  • Stores in the Gin context: response.StartTimeContextKey (time.Now()), response.TraceIDContextKey, response.VersionContextKey, response.EnvContextKey — the responder turns these into api_info.{trace_id, latency, version, env}. Also stores the commit under the private key "api_commit".
  • Lưu vào Gin context: response.StartTimeContextKey (time.Now()), response.TraceIDContextKey, response.VersionContextKey, response.EnvContextKey — responder biến chúng thành api_info.{trace_id, latency, version, env}. Commit được lưu dưới key riêng "api_commit".
  • Never aborts.
  • Không bao giờ abort.

funcCORScors.go
func CORS(opts CORSOptions) gin.HandlerFunc
  • If the request has an Origin that is allowed (listed, or the list contains "*"):
    • "*" and AllowCredentials == false → Access-Control-Allow-Origin: *
    • otherwise → Access-Control-Allow-Origin: <the request's Origin> + Vary: Origin
    • AllowCredentials → Access-Control-Allow-Credentials: true
  • Nếu request có Origin được phép (có trong danh sách, hoặc danh sách chứa "*"):
    • "*" và AllowCredentials == false → Access-Control-Allow-Origin: *
    • ngược lại → Access-Control-Allow-Origin: <Origin của request> + Vary: Origin
    • AllowCredentials → Access-Control-Allow-Credentials: true
  • A disallowed origin is not rejected — it just gets no allow-origin header, so the browser hides the response.

Good to knowCần lưu ý

1Order is behaviourA middleware only affects what comes after it. In Jungo's order, CORS preflights (204) and Payload's 413 abort before AccessLog, so they are never access-logged; anything that answers before Trace has no trace ID. Recover protects only what runs after it — a panic inside an earlier middleware is not turned into a JSON 500.Một middleware chỉ ảnh hưởng tới những gì đứng sau nó. Theo thứ tự của Jungo, preflight CORS (204) và 413 của Payload abort trước AccessLog nên không bao giờ được ghi access log; cái gì trả lời trước Trace sẽ không có trace ID. Recover chỉ bảo vệ những gì chạy sau nó — panic trong một middleware đứng trước không được biến thành JSON 500.
2Limiter: zero durations crashCleanupInterval or LogTTL of 0 makes time.NewTicker panic inside a background goroutine, which kills the whole process at startup. Always set both (and ClientTTL).Nếu đặt CleanupInterval hoặc LogTTL bằng 0, time.NewTicker sẽ panic trong goroutine nền khiến toàn bộ ứng dụng bị crash ngay khi khởi động. Hãy luôn cấu hình thời gian hợp lệ cho cả hai (cùng với ClientTTL).
3Limiter keys on ClientIP()Behind a load balancer without SECURITY_TRUSTED_PROXIES, every client has the balancer's IP and shares one bucket. Behind a reverse proxy on the same host, every request comes from 127.0.0.1 — which is in Jungo's default whitelist, so nothing is limited. Set trusted proxies to your proxy addresses.Đứng sau load balancer mà không có SECURITY_TRUSTED_PROXIES, mọi client mang IP của balancer và dùng chung một bucket. Đứng sau reverse proxy cùng máy, mọi request đến từ 127.0.0.1 — nằm trong whitelist mặc định của Jungo, nên không có gì bị giới hạn. Hãy đặt trusted proxies là địa chỉ proxy của bạn.
4Limiter: User-Agent bypass, per processAny client sending User-Agent: PostmanRuntime/… or GoHttpTest/… skips the limit — the header is client-controlled. Buckets live in process memory: with N instances, a client effectively gets N× the rate.Client nào gửi User-Agent: PostmanRuntime/… hoặc GoHttpTest/… đều bỏ qua giới hạn — header này do client tự đặt. Bucket nằm trong bộ nhớ process: với N instance, một client thực tế được N lần tốc độ.
5CORS "*" + credentialsWith "*" and AllowCredentials: true (Jungo's defaults), any origin is echoed back with Access-Control-Allow-Credentials: true — every website may make credentialed calls. List real origins in production. Also: disallowed origins are not blocked server-side, and every OPTIONS gets 204.Với "*" và AllowCredentials: true (mặc định của Jungo), mọi origin đều được trả lại kèm Access-Control-Allow-Credentials: true — website nào cũng gọi kèm credentials được. Trong production hãy liệt kê origin thật. Ngoài ra: origin không được phép không bị chặn ở server, và mọi OPTIONS đều nhận 204.
6Payload buffers everythingThe whole body (uploads included — Payload is global) is read into memory, so MaxBodySize is also your upload limit. 0 means "reject every body". A client that disconnects mid-body also gets 413.Toàn bộ body (kể cả file upload — Payload là global) được đọc vào bộ nhớ, nên MaxBodySize cũng chính là giới hạn upload. 0 nghĩa là "từ chối mọi body". Client ngắt kết nối giữa chừng cũng nhận 413.
7AccessLog masking has limitsCustom SensitiveFields / ExcludedPaths replace the defaults (add the defaults back yourself). The query string is logged raw — never put secrets in URLs. Masking edits the cached payload map in place, after the handler has run.SensitiveFields / ExcludedPaths tự đặt sẽ thay thế mặc định (tự thêm lại mặc định nếu cần). Query string được ghi nguyên văn — đừng đặt secret trên URL. Việc che sửa trực tiếp map payload đã cache, sau khi handler chạy xong.
8Debug mode in productionAnyone with the key/value and AUTH_INTERNAL_SECRET gets the full trace (SQL, timings) of any endpoint, and the handler really runs (writes still hit the database). Debug requests are not access-logged. Keep the secret strong; leaving AUTH_INTERNAL_SECRET or TRACER_DEBUG_VALUE empty turns debug mode off.Ai có key/value và AUTH_INTERNAL_SECRET đều xem được toàn bộ trace (SQL, thời gian) của mọi endpoint, và handler chạy thật (ghi database vẫn xảy ra). Request debug không được ghi access log. Hãy dùng secret đủ mạnh; để AUTH_INTERNAL_SECRET hoặc TRACER_DEBUG_VALUE rỗng là tắt chế độ debug.
9HSTS needs TLS in GoStrict-Transport-Security is only sent when Go itself terminated TLS (c.Request.TLS != nil). Behind a TLS-terminating proxy, set HSTS at the proxy.Strict-Transport-Security chỉ được gửi khi chính Go xử lý TLS (c.Request.TLS != nil). Đứng sau proxy xử lý TLS thì đặt HSTS ở proxy.
10Trusted inputsAn incoming X-Trace-Id is reused without validation. In an Authenticator, return *response.AppError for bad tokens — a plain errors.New becomes a 500.X-Trace-Id gửi lên được dùng lại mà không kiểm tra. Trong Authenticator, hãy trả *response.AppError cho token sai — errors.New thông thường sẽ thành 500.
11Gzip: compress onceIf nginx, an ingress or a CDN in front already compresses, leave Gzip out — it costs CPU for nothing. Put it after CORS so preflights skip it; responses written by middleware before it (TracerDebug's dashboard) are not compressed. c.Writer.Size() in AccessLog reports compressed bytes.Nếu nginx, ingress hoặc CDN phía trước đã nén, đừng dùng Gzip — tốn CPU vô ích. Đặt nó sau CORS để preflight không đi qua; response do middleware đứng trước ghi (dashboard của TracerDebug) không được nén. c.Writer.Size() trong AccessLog sẽ là số byte đã nén.
12RoutePatterns: names are globalA rule applies to every route with that parameter name. A route that takes free text in :id or :slug starts returning 404 — rename the parameter (:key, :code).Rule áp dụng cho mọi route có param cùng tên. Route nhận chuỗi tự do qua :id hay :slug sẽ bắt đầu trả 404 — hãy đổi tên param (:key, :code).
