Junkit · notification

notification

Turns "something went wrong in a request" into a readable Telegram alert — banner, request info, error location, a ready-to-run curl and an attached stack trace. Best-effort: it never returns an error.

Tự động chuyển tiếp lỗi trong request thành tin nhắn cảnh báo Telegram trực quan — gồm banner phân loại, thông tin request, vị trí file/dòng code gây lỗi, lệnh curl để tái hiện nhanh và file đính kèm stack trace. Cơ chế Best-effort: không bao giờ trả lỗi ngược lại làm gián đoạn luồng xử lý chính.

What it doesNó làm gì

Middleware (or your code) calls the Notifier; it formats Telegram HTML and hands it to telegram.Client. Every send error is dropped.

Middleware (hoặc code ứng dụng) gọi Notifier; package định dạng nội dung HTML theo chuẩn Telegram rồi gửi qua telegram.Client. Nếu gửi thất bại, lỗi được bỏ qua an toàn để không ảnh hưởng request của người dùng.

Use it in 30 secondsDùng ngay trong 30 giây

Panics are already covered by middleware.Recover. Call the Notifier yourself for errors you handle. Hover an explanation to light up its lines.

Panic đã được middleware.Recover lo. Tự gọi Notifier cho các lỗi bạn xử lý. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

order_handler.go
type OrderHandler struct {
    service   OrderService // your own
    notifier  notification.Notifier
    responder response.Responder
}

func (h *OrderHandler) Create(c *gin.Context) {
    order, err := h.service.Create(c.Request.Context())
    if err != nil {
        _, file, line, _ := runtime.Caller(0)
        h.notifier.SendErrorNotification(c, map[string]any{
            "error":    err.Error(),
            "location": file,
            "function": "OrderHandler.Create",
            "line":     line,
        }, http.StatusBadGateway)
        h.responder.Error(c, err)
        return
    }

    if order.Total > 10_000 {
        msg := "Big order <code>" +
            html.EscapeString(order.ID) + "</code>"
        go h.notifier.SendMessageHTML(c.Copy(), msg, "warning")
    }

    h.responder.SendWithData(c, http.StatusCreated,
        "order_created", order)
}

interfaceNotifier
            

            

              
type Notifier interface {
	SendMessageHTML(c *gin.Context, message string, typeMessage string)
	SendErrorNotification(c *gin.Context, errData map[string]any, statusCode int, sql ...string)
}


            

            
No return values: delivery is best-effort and errors from telegram.Client are
              discarded. Both methods send with context.Background(), so only the *http.Client
              timeout bounds them.

            
Không có giá trị trả về: gửi theo kiểu best-effort và error từ telegram.Client bị
              bỏ đi. Cả hai method gửi với context.Background(), nên chỉ timeout của
              *http.Client giới hạn chúng.

methodNotifier.SendErrorNotification

            

              
SendErrorNotification(c *gin.Context, errData map[string]any, statusCode int, sql ...string)

            

            
Returns immediately unless Options.Environment == "production". Otherwise builds
              the alert below. If errData["stack"] is a non-empty string it calls SendDocument
              instead of SendMessage: file stack-YYYYMMDD-HHMMSS.txt (content
              STACK TRACE\nGenerated: <time>\n----------------------------------------\n\n<stack>),
              caption = alert + "\n\n📄 <b>Full stack trace attached above</b>".

            
Trả về ngay trừ khi Options.Environment == "production". Ngược lại nó dựng cảnh
              báo bên dưới. Nếu errData["stack"] là chuỗi khác rỗng, nó gọi SendDocument thay
              vì SendMessage: file stack-YYYYMMDD-HHMMSS.txt (nội dung
              STACK TRACE\nGenerated: <time>\n----------------------------------------\n\n<stack>),
              caption = cảnh báo + "\n\n📄 <b>Full stack trace attached above</b>".
