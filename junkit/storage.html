What it doesNó làm gì

The shipped LocalService writes into BaseDir under a fresh unique name and returns BaseURL + that name. Your router serves BaseDir at the same path.

LocalService có sẵn ghi vào BaseDir với một tên mới duy nhất và trả về BaseURL + tên đó. Router của bạn phục vụ BaseDir tại đúng đường dẫn ấy.

SetupCài đặt

With Fx (how Jungo does it) or with the plain constructor.

Dùng Fx (cách Jungo làm) hoặc gọi thẳng constructor.

internal/app/fx.go
// in CoreModules(cfg):
fx.Provide(provideStorageOptions),
storage.Module,

// provideStorageOptions builds storage.Options from cfg.Storage.
func provideStorageOptions(cfg *config.Config) storage.Options {
    return storage.Options{BaseDir: cfg.StoragePath("uploads"), BaseURL: cfg.Storage.BaseURL}
}
internal/router/router.go · registerUploads
uploads := p.Router.Group("/uploads",
    // Cross-origin: uploaded images are embedded by the frontend, which may be on another site.
    middleware.Security(middleware.SecurityOptions{
        ForceHSTS:                 p.Config.Security.ForceHSTS,
        CrossOriginResourcePolicy: "cross-origin",
    }),
    middleware.Recover(middleware.RecoverOptions{}, p.HTTPLogger, p.Notifier, p.Responder),
)
uploads.Static("/", p.Config.StoragePath("uploads"))

The group is registered before the global middleware, so files skip gzip, the access log and body parsing but keep the security headers (X-Content-Type-Options: nosniff matters for user files) and panic recovery. Serve BaseDir the same way in your own router.

Group này được đăng ký trước middleware toàn cục, nên file bỏ qua gzip, access log và đọc body nhưng vẫn giữ header bảo mật (X-Content-Type-Options: nosniff quan trọng với file của người dùng) và recover panic. Hãy phục vụ BaseDir theo cùng cách trong router của bạn.

Any constructor can now take a storage.Service. If the directory cannot be created, NewService returns an error and Fx refuses to start.

Giờ mọi constructor đều có thể nhận storage.Service. Nếu không tạo được thư mục, NewService trả lỗi và Fx không khởi động.

Quick startDùng nhanh

Replace a document's attachment safely — the same pattern Jungo uses for avatars. Hover an explanation to light up its lines.

Thay file đính kèm của một tài liệu một cách an toàn — đúng mẫu Jungo dùng cho avatar. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

document_service.go
type DocumentService struct {
    repo    domain.DocumentRepository
    storage storage.Service
}

func (s *DocumentService) ReplaceFile(ctx context.Context, id uuid.UUID,
    file io.Reader, filename string) (string, error) {
    doc, err := s.repo.Get(ctx, id)
    if err != nil {
        return "", err
    }

    url, err := s.storage.UploadFile(ctx, file, filename)
    if err != nil {
        return "", err
    }

    if err := s.repo.SetFileURL(ctx, id, url); err != nil {
        _ = s.storage.DeleteFile(ctx, url) // undo the upload
        return "", err
    }

    if doc.FileURL != "" {
        _ = s.storage.DeleteFile(ctx, doc.FileURL) // drop the old file
    }

    return url, nil
}

type Service interface {

  • DeleteFile removes a file given the URL UploadFile returned.
  • DeleteFile xóa file dựa trên URL mà UploadFile đã trả.

typeLocalServicefuncNewLocalService
type LocalService struct { /* baseDir, baseURL — unexported */ }

func NewLocalService(opts Options) (*LocalService, error)
  • Runs os.MkdirAll(opts.BaseDir, os.ModePerm) immediately and trims a trailing / from opts.BaseURL.
  • Chạy os.MkdirAll(opts.BaseDir, os.ModePerm) ngay lập tức và cắt dấu / cuối của opts.BaseURL.
  • Error: storage: create base dir: <cause> (wrapped, use errors.Is / errors.As).
  • Lỗi: storage: create base dir: <cause> (được wrap, dùng errors.Is / errors.As).
  • The directory is created with os.ModePerm and files with os.Create, so their permissions are 0777 / 0666 minus the process umask.
  • Thư mục được tạo với os.ModePerm và file với os.Create, nên quyền của chúng là 0777 / 0666 trừ đi umask của tiến trình.
  • Holds no lock and no open files — safe to share between goroutines.
  • Không giữ lock hay file nào mở — dùng chung giữa các goroutine an toàn.
method(*LocalService) UploadFile
func (s *LocalService) UploadFile(ctx context.Context, file io.Reader, originalFilename string) (string, error)
  • Stored name: <uuid v4>_<unix seconds><ext>, where ext is filepath.Ext(originalFilename) lowercased. Two uploads with the same name never collide.
  • Tên lưu: <uuid v4>_<unix giây><ext>, với ext là filepath.Ext(originalFilename) chuyển chữ thường. Hai lần upload cùng tên không bao giờ đụng nhau.
  • No extension, or one a browser could run when served back (.html .htm .xhtml .xht .shtml .svg .svgz .js .mjs .xml .xsl .xslt .swf) → ErrUnsafeExtension, nothing written.
  • Không có phần mở rộng, hoặc là loại trình duyệt có thể chạy khi phục vụ lại (.html .htm .xhtml .xht .shtml .svg .svgz .js .mjs .xml .xsl .xslt .swf) → ErrUnsafeExtension, không ghi gì.
  • Returns baseURL + "/" + name.
  • Trả về baseURL + "/" + name.
  • Errors: storage: create file: …, storage: copy file: …, storage: close file: …. On a copy or close error the partial file is removed.
  • Lỗi: storage: create file: …, storage: copy file: …, storage: close file: …. Khi copy hoặc close lỗi, file ghi dở được xóa.
  • ctx is checked before every read, so a cancelled request stops the copy (storage: copy file: context canceled) and the partial file is removed.
  • ctx được kiểm tra trước mỗi lần đọc, nên request bị huỷ sẽ dừng việc copy (storage: copy file: context canceled) và file ghi dở được xóa.
method(*LocalService) DeleteFile
func (s *LocalService) DeleteFile(_ context.Context, fileURL string) error
  • fileURL must be BaseURL + "/" + name; it removes BaseDir/<name>. Only a plain file name directly inside BaseDir is accepted, so the delete can never leave BaseDir.
  • fileURL phải là BaseURL + "/" + tên; nó xóa BaseDir/<tên>. Chỉ chấp nhận một tên file thuần nằm ngay trong BaseDir, nên lệnh xóa không bao giờ ra khỏi BaseDir.
  • A file that does not exist → nil.
  • File không tồn tại → nil.
  • A URL without the BaseURL + "/" prefix, or a name that is "", ".", ".." or contains / or \ → ErrInvalidURL. Any other removal failure → storage: delete file: ….
  • URL không có tiền tố BaseURL + "/", hoặc tên là "", ".", ".." hay chứa / hoặc \ → ErrInvalidURL. Lỗi xóa khác → storage: delete file: ….

Good to knowCần lưu ý

1No content checksKhông kiểm tra nội dungUploadFile only refuses missing and active-content extensions (HTML, SVG, scripts — stored XSS on the API origin); it stores any bytes under any other extension. Files under /uploads are public, so allow-list extensions, cap the size and check the first bytes before calling it (upload.Open does all three).UploadFile chỉ từ chối khi không có phần mở rộng hoặc là loại chạy được (HTML, SVG, script — stored XSS trên origin của API); với phần mở rộng khác nó lưu mọi loại byte. File trong /uploads là công khai, nên hãy giới hạn phần mở rộng theo danh sách cho phép, giới hạn kích thước và kiểm tra các byte đầu trước khi gọi (upload.Open làm cả ba).
2Half-written files are removedFile ghi dở bị xóaIf io.Copy fails midway or the final Close fails, UploadFile removes the partial file and returns the error.Nếu io.Copy lỗi giữa chừng hoặc lần Close cuối lỗi, UploadFile xóa file ghi dở và trả lỗi.
3Full URLs are storedLưu URL đầy đủThe DB keeps BaseURL/<name>. Changing STORAGE_BASE_URL later does not rewrite old rows, and DeleteFile then refuses those old URLs with ErrInvalidURL — migrate the rows when you change it.DB lưu BaseURL/<name>. Đổi STORAGE_BASE_URL sau này không sửa các dòng cũ, và DeleteFile khi đó từ chối các URL cũ với ErrInvalidURL — hãy cập nhật các dòng khi đổi.
4DeleteFile checks the prefixDeleteFile kiểm tra tiền tốOnly BaseURL + "/" + name deletes; anything else is ErrInvalidURL. Any URL of that form deletes BaseDir/<name>, so never pass a client-supplied URL straight to DeleteFile.Chỉ BaseURL + "/" + tên mới xóa được; còn lại là ErrInvalidURL. Mọi URL đúng dạng đó đều xóa BaseDir/<tên>, nên đừng bao giờ truyền thẳng URL do client gửi vào DeleteFile.
