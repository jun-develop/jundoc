Use it in 30 secondsDùng ngay trong 30 giây

A tiny DBTX decorator that logs every Exec — plug it into postgres.Options.Decorate. Hover an explanation.

Một decorator DBTX nhỏ log mọi lệnh Exec — gắn vào postgres.Options.Decorate. Rê chuột vào phần giải thích.

exec_logger.go
type execLogger struct {
    postgres.DBTX
    log *zap.Logger
}

func (l execLogger) Exec(ctx context.Context, sql string, args ...any) (pgconn.CommandTag, error) {
    tag, err := l.DBTX.Exec(ctx, sql, args...)

    info := sqlfmt.Parse(sql)
    fields := []zap.Field{
        zap.String("query", info.Name),
        zap.String("op", info.Operation),
        zap.String("sql", sqlfmt.Bind(info.SQL, args)),
    }
    if err != nil {
        fields = append(fields, zap.Error(err))
    }
    l.log.Info("exec", fields...)
    return tag, err
}

// wire it: postgres.Options{Decorate: func(inner postgres.DBTX) postgres.DBTX {
//     return execLogger{DBTX: inner, log: log}
// }}

typeInfo

            

              
type Info struct {
    // Name is the sqlc query name, or a guess from the leading keyword.
    Name string

    // Operation is the sqlc operation (ONE, MANY, EXEC, ...), empty if unannotated.
    Operation string

    // SQL is the query with comments stripped and whitespace collapsed.
    SQL string
}


            

            

              

                

                  field
                  filled fromlấy từ
                

                

                  Name
                  The first match of -- name: <Name> :<op>. Without it, from the
                    first word of the cleaned SQL (case-insensitive): SELECT → "Select", INSERT →
                    "Insert", UPDATE → "Update", DELETE → "Delete", WITH →
                    "With", anything else (or empty SQL) → "Query".
                  Kết quả khớp đầu tiên của -- name: <Name> :<op>. Nếu không có,
                    lấy từ chữ đầu tiên của SQL đã làm sạch (không phân biệt hoa thường): SELECT →
                    "Select", INSERT → "Insert", UPDATE → "Update", DELETE →
                    "Delete", WITH → "With", còn lại (hoặc SQL rỗng) → "Query".
                  
                

                

                  Operation
                  The :op part, upper-cased (:one → "ONE",
                    :execrows → "EXECROWS"). Empty without an annotation.
                  Phần :op, viết hoa (:one → "ONE",
                    :execrows → "EXECROWS"). Rỗng nếu không có chú thích.
                

                

                  SQL
                  Every --  comment (dash dash space, to end of line) removed,
                    trimmed, every whitespace run → one space. Placeholders stay as $n.
                  Mọi comment --  (hai gạch + dấu cách, tới cuối dòng) bị xoá, cắt
                    khoảng trắng hai đầu, mỗi chuỗi khoảng trắng → một dấu cách. Placeholder giữ nguyên dạng
                    $n.
                

              

            

          


          

            
funcParse

            

              
func Parse(sql string) Info

            

            
Returns the Info for sql. Results are cached in a
              sync.Map keyed by the exact SQL string, for up to 1024 distinct strings; beyond that it still
              parses correctly, just without caching. Never fails.

            
Trả Info của sql. Kết quả được cache trong sync.Map với
              key là nguyên chuỗi SQL, tối đa 1024 chuỗi khác nhau; vượt quá thì vẫn parse đúng, chỉ là không cache.
              Không bao giờ lỗi.

            

              
sqlfmt.Parse("-- name: GetUserByUUID :one\nSELECT * FROM users WHERE uuid = $1")
// Info{Name: "GetUserByUUID", Operation: "ONE", SQL: "SELECT * FROM users WHERE uuid = $1"}

sqlfmt.Parse("SELECT *\n  -- this is a comment\n  FROM   users\nWHERE  id = 1")
// Info{Name: "Select", Operation: "", SQL: "SELECT * FROM users WHERE id = 1"}


            

          


          

            
funcBind

            

              
func Bind(sql string, args []any) string

            

            
    
              
  • Replaces each $n (n = 1…len(args), multi-digit OK) with
                FormatValue(args[n-1]).
    • 
              
  • Thay mỗi $n (n = 1…len(args), nhiều chữ số vẫn được) bằng
                FormatValue(args[n-1]).
    • 
              
  • args empty → sql returned unchanged. $0, out-of-range
                $n and a $ not followed by a digit are left as-is.
    • 
              
  • args rỗng → trả nguyên sql. $0, $n ngoài
                phạm vi và $ không theo sau bởi chữ số được giữ nguyên.
    • 
              
  • Simple text scan: it does not know about string literals or comments.
    • 
              
  • Chỉ quét chuỗi đơn giản: nó không biết gì về string literal hay comment.
    • 
            

            

              
sqlfmt.Bind("INSERT INTO users (email, status) VALUES ($1, $2)", []any{"jane@example.com", 1})
// "INSERT INTO users (email, status) VALUES ('jane@example.com', 1)"

sqlfmt.Bind("SELECT $1, $5", []any{"only one arg"})
// "SELECT 'only one arg', $5"


            

          


          

            
funcBindQuestion

            

              
func BindQuestion(sql string, args []any) string

            

            
    
              
  • Bind for drivers with positional ? placeholders (MySQL,
                ClickHouse, SQLite): the n-th ? becomes FormatValue(args[n-1]).
    • 
              
  • Bind cho các driver dùng placeholder ? theo vị trí (MySQL,
                ClickHouse, SQLite): dấu ? thứ n được thay bằng FormatValue(args[n-1]).
    • 
              
  • args empty → sql returned unchanged. Extra ? beyond
                len(args) are left as-is.
    • 
              
  • args rỗng → trả nguyên sql. Các ? dư ra ngoài
                len(args) được giữ nguyên.
    • 
              
  • Unlike Bind, a ? inside a single-quoted string is skipped.
    • 
              
  • Khác với Bind, dấu ? nằm trong chuỗi nháy đơn được bỏ qua.
    • 
            

            

              
sqlfmt.BindQuestion("SELECT * FROM users WHERE email = ? AND note = '?'", []any{"jane@example.com"})
// "SELECT * FROM users WHERE email = 'jane@example.com' AND note = '?'"

funcOrigin

            

              
func Origin() (location, function string)

            

            
Walks the current goroutine's stack (from its caller, at most 32 frames) and returns the first
              frame that is not runtime.*, pgx, Junkit database / tracer /
              sqlfmt, or a sqlc-generated *.sql.go file. location is
              "/abs/path/file.go:123", function the fully-qualified name (e.g.
              jungo/internal/features/user/repository.(*UserRepository).Create). If every frame is skipped:
              "unknown", "unknown".

            
Duyệt stack của goroutine hiện tại (từ hàm gọi nó, tối đa 32 frame) và trả frame đầu tiên không
              phải runtime.*, pgx, database / tracer / sqlfmt của
              Junkit, hay file sqlc sinh ra *.sql.go. location là
              "/abs/path/file.go:123", function là tên đầy đủ (vd.
              jungo/internal/features/user/repository.(*UserRepository).Create). Nếu mọi frame đều bị bỏ
              qua: "unknown", "unknown".

            
It must be called synchronously, on the goroutine that ran the query — which is the case inside
              pgx tracers and DBTX wrappers.

            
Phải gọi đồng bộ, trên chính goroutine đã chạy query — điều này đúng khi ở trong tracer của pgx
              và wrapper DBTX.

Good to knowCần lưu ý

          

        

        

          
1Never execute Bind's
              outputThe quoting is just enough to read; it is not an escaping function.
              Always run the original sql with args.Cách đặt
              nháy chỉ đủ để đọc; đây không phải hàm escape. Luôn chạy sql gốc kèm
              args.

          
2Values end up in
              logsBound SQL contains real data — emails, hashes, tokens. Treat anything
              built with Bind as sensitive.SQL đã bind chứa dữ liệu thật —
              email, hash, token. Hãy coi mọi thứ tạo bởi Bind là nhạy cảm.

          
3Text-only
              cleaningParse and Bind don't understand SQL:
              '$1' or 'a -- b' inside a string literal is replaced / cut too, spaces inside
              literals are collapsed, and --comment without a space after the dashes is not removed.
              The logged SQL may therefore differ slightly from what ran.Parse và Bind không hiểu SQL: '$1' hay
              'a -- b' nằm trong string literal cũng bị thay / cắt, khoảng trắng trong literal bị gộp, và
              --comment không có dấu cách sau hai gạch thì không bị xoá. Vì vậy SQL được log có thể
              hơi khác so với SQL đã chạy.

          
4Lossy
              literalstime.Time loses sub-second precision;
              []byte is a slice, so it prints as '{104,105}'; unsupported pgtype values (e.g.
              pgtype.Numeric, pgtype.Float8) print their Go struct with
              %v.time.Time mất phần lẻ giây;
              []byte là slice nên in ra '{104,105}'; các giá trị pgtype không hỗ trợ (vd.
              pgtype.Numeric, pgtype.Float8) in struct Go bằng %v.

          
5Origin and your own
              wrappersOnly Junkit's database, tracer,
              sqlfmt, pgx, runtime and *.sql.go frames are skipped. If you call
              Origin from your own logging wrapper, it returns the wrapper's line, not the repository's.
              Deep stacks (> 32 frames above it) can also yield "unknown".Chỉ các frame của database, tracer, sqlfmt (Junkit), pgx,
              runtime và *.sql.go bị bỏ qua. Nếu bạn gọi Origin từ wrapper log của riêng mình,
              nó trả dòng của wrapper, không phải của repository. Stack quá sâu (> 32 frame phía trên) cũng có thể
              cho "unknown".

          
6Dynamic SQL and the
              cacheThe cache key is the full SQL text. SQL built with inlined values
              fills the 1024 slots quickly; after that, new strings are parsed on every call (correct, just slower). Use
              placeholders.Key của cache là toàn bộ chuỗi SQL. SQL dựng bằng cách nhét
              giá trị trực tiếp sẽ nhanh chóng lấp đầy 1024 chỗ; sau đó chuỗi mới bị parse ở mỗi lần gọi (vẫn đúng, chỉ
              chậm hơn). Hãy dùng placeholder.
