Junkit · logger

logger

Builds a *zap.Logger from a plain Options struct: coloured console output in development, rotating JSON files everywhere else — plus named channels and a trace ID carried in context.Context.

Tạo một *zap.Logger từ struct Options đơn giản: in màu ra console khi development, ghi file JSON có xoay vòng (rotate) ở mọi môi trường khác — kèm các kênh log có tên và trace ID mang theo trong context.Context.

What it doesNó làm gì

You describe the logger with data; New picks the encoder and the destination. A second, independent path carries the request's trace ID so every log line can be tied to one request.

Bạn mô tả logger bằng dữ liệu; New chọn encoder và nơi ghi. Một luồng thứ hai, độc lập, mang trace ID của request để mỗi dòng log đều gắn được với đúng một request.

Wire it upKết nối vào app

Three ways, from the one Jungo uses to no Fx at all.

Ba cách, từ cách Jungo đang dùng tới hoàn toàn Không dùng Fx.

Jungo builds four channels — app, http, sql, limiter — each with its own level and file, sharing the environment and rotation settings. Quoted from internal/app/fx.go:

Jungo tạo bốn kênh — app, http, sql, limiter — mỗi kênh có level và file riêng, dùng chung environment và thiết lập xoay vòng. Trích từ internal/app/fx.go:

internal/app/fx.go
// CoreModules(cfg) …
fx.Options(provideLoggers(cfg)...),

fx.Module("database",
    fx.Decorate(fx.Annotate(
        func(sqlLogger *zap.Logger) *zap.Logger { return sqlLogger },
        fx.ParamTags(`name:"sql"`),
    )),
    primary.Module,
),

// provideLoggers builds the app/http/sql/limiter named logging channels.
func provideLoggers(cfg *config.Config) []fx.Option {
    shared := logger.Options{
        Environment: cfg.Environment,
        Output:      cfg.Logger.Output,
        MaxSize:     cfg.Logger.MaxSize,
        MaxBackups:  cfg.Logger.MaxBackups,
        MaxAge:      cfg.Logger.MaxAge,
        Compress:    cfg.Logger.Compress,
    }

    defs := []logger.Definition{
        {Name: "app", Level: cfg.Logger.AppLevel, Filename: cfg.Logger.AppFilename},
        {Name: "http", Level: cfg.Logger.HTTPLevel, Filename: cfg.Logger.HTTPFilename},
        {Name: "sql", Level: cfg.Logger.SQLLevel, Filename: cfg.Logger.SQLFilename},
        {Name: "limiter", Level: cfg.Logger.LimiterLevel, Filename: cfg.Logger.LimiterFilename},
    }

    return logger.ProvideNamed(defs, shared)
}

The fx.Decorate swaps the default logger for the sql one inside the database module only — so SQL logs land in their own file.

fx.Decorate thay logger mặc định bằng kênh sql chỉ bên trong module database — nhờ vậy log SQL nằm ở file riêng.

One logger, untagged. logger.Module needs a logger.Options value in the container — supply it or provide it from your config.

Một logger, không gắn tag. logger.Module cần có một giá trị logger.Options trong container — dùng fx.Supply hoặc provide nó từ config.

main.go
fx.New(
    fx.Supply(logger.Options{
        Environment: "production",
        Level:       "info",
        Filename:    "logs/app.log",
        MaxSize:     10, // MB
        MaxBackups:  5,
        MaxAge:      7, // days
        Compress:    true,
    }),
    logger.Module, // provides *zap.Logger
    fx.Invoke(func(log *zap.Logger) { log.Info("ready") }),
).Run()

New takes an fx.Lifecycle only to register its flush hook. Outside Fx, pass anything with an Append(fx.Hook) method (the package tests do exactly this) and call Sync yourself.

New nhận fx.Lifecycle chỉ để đăng ký hook flush. Không dùng Fx thì truyền bất kỳ thứ gì có method Append(fx.Hook) (test của package làm đúng như vậy) và tự gọi Sync.

main.go
type noLifecycle struct{}

func (noLifecycle) Append(fx.Hook) {} // hooks ignored; we flush below

func main() {
    log, err := logger.New(noLifecycle{}, logger.Options{
        Environment: "development",
        Level:       "debug",
    })
    if err != nil {
        panic(err)
    }
    defer log.Sync()

Use it in 30 secondsDùng ngay trong 30 giây

A service that logs with the request's trace ID. Hover an explanation to light up its lines.

Một service ghi log kèm trace ID của request. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

user_service.go
type UserService struct {
    log  *zap.Logger // untagged = "app" channel
    repo UserRepository
}

func NewUserService(log *zap.Logger,
    repo UserRepository) *UserService {
    return &UserService{log: log, repo: repo}
}

func (s *UserService) Create(ctx context.Context,
    email string) error {
    // set by middleware.Trace for HTTP requests
    traceID := logger.GetTraceID(ctx)
    s.log.Debug("creating user",
        zap.String("trace_id", traceID))

    if err := s.repo.Insert(ctx, email); err != nil {
        s.log.Error("insert user failed",
            zap.String("trace_id", traceID),
            zap.Error(err))
        return err
    }
    return nil
}

// Another channel? Ask for it by its name tag.
type AuditParams struct {
    fx.In
    HTTPLog *zap.Logger `name:"http"`
}
