What it doesNó làm gì

Two methods, one HTTP call each. If the token or chat id is missing, the call stops at the guard: a Warn log, nil returned, nothing sent.

cfg.Telegram.Token comes from the env var TELEGRAM_BOT_TOKEN (config.TelegramConfig). The chat id (TELEGRAM_CHAT_ID) is not an option — it is passed on every call.

Use it in 30 secondsDùng ngay trong 30 giây

Report a finished job: one message, one CSV attachment. Hover an explanation to light up its lines.

Báo cáo một job đã chạy xong: một tin nhắn và một file CSV đính kèm. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

report.go
type Reporter struct {
    tg     telegram.Client // from telegram.Module
    chatID string
}

func (r *Reporter) Done(ctx context.Context, job string,
    csv []byte) error {
    ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
    defer cancel()

    msg := "<b>Job finished</b> ✅\n" +
        "<code>" + html.EscapeString(job) + "</code>"
    if err := r.tg.SendMessage(ctx, r.chatID, msg); err != nil {
        return fmt.Errorf("notify: %w", err)
    }

    return r.tg.SendDocument(ctx, r.chatID,
        bytes.NewReader(csv), "report.csv", "<i>Daily report</i>")
}

API referenceTham chiếu API

Everything the package exports — signatures copied from junkit/telegram/telegram.go and module.go.

Mọi thứ package export — chữ ký chép từ junkit/telegram/telegram.go và module.go.

interfaceClient
type Client interface {
	SendMessage(ctx context.Context, chatID, message string) error
	SendDocument(ctx context.Context, chatID string, content io.Reader, filename string, caption string) error
}

The only thing you depend on. The default implementation is unexported and returned by NewClient. Safe for concurrent use (it holds no mutable state; it shares one *http.Client).

Thứ duy nhất bạn phụ thuộc vào. Bản cài đặt mặc định không export, được trả về bởi NewClient. An toàn khi dùng đồng thời (không giữ state thay đổi; dùng chung một *http.Client).

methodClient.SendMessage
SendMessage(ctx context.Context, chatID, message string) error
  • POST https://api.telegram.org/bot<token>/sendMessage, Content-Type: application/json, body {"chat_id": chatID, "text": message, "parse_mode": "HTML"}.
  • POST https://api.telegram.org/bot<token>/sendMessage, Content-Type: application/json, body {"chat_id": chatID, "text": message, "parse_mode": "HTML"}.
  • Empty token or empty chatID → logs Warn telegram: skip sending message due to missing token or chat_id and returns nil.
  • Token hoặc chatID trống → log Warn telegram: skip sending message due to missing token or chat_id và trả nil.
  • Returns the raw error (and logs Error) when encoding, building or sending the request fails. Log lines: telegram: encode message failed, telegram: build request failed, telegram: send message failed.
  • Trả error gốc (và log Error) khi encode, tạo hoặc gửi request thất bại. Các dòng log: telegram: encode message failed, telegram: build request failed, telegram: send message failed.
  • Any status other than 200 → logs telegram: api returned error (with status) and returns telegram api error (status %d): %s, where %s is Telegram's response body.
  • Status khác 200 → log telegram: api returned error (kèm status) và trả telegram api error (status %d): %s, với %s là body response của Telegram.
methodClient.SendDocument
SendDocument(ctx context.Context, chatID string, content io.Reader, filename string, caption string) error
  • POST …/sendDocument as multipart/form-data: field chat_id, file field document named filename, and — only when caption != "" — fields caption and parse_mode=HTML.
  • POST …/sendDocument dạng multipart/form-data: field chat_id, field file document tên filename, và — chỉ khi caption != "" — các field caption và parse_mode=HTML.
  • The body is written by a goroutine into an io.Pipe while the request is sent: memory use stays flat whatever the size of content. Exception: an injected client with httpclient.Options.MaxRetries > 0 reads the whole body into memory first so it can resend it. The reader is read to EOF but not closed — close files yourself. If building or sending the request fails, the pipe is closed so the writer goroutine stops (no leak).
  • Body được một goroutine ghi vào io.Pipe trong khi request đang gửi: bộ nhớ không tăng theo kích thước content. Ngoại lệ: client được inject có httpclient.Options.MaxRetries > 0 sẽ đọc toàn bộ body vào bộ nhớ trước để có thể gửi lại. Reader được đọc tới EOF nhưng không bị đóng — tự đóng file của bạn. Nếu tạo hoặc gửi request lỗi, pipe được đóng để goroutine ghi dừng lại (không rò rỉ).
  • Empty token, empty chatID or content == nil → logs Warn telegram: skip sending document due to invalid parameters, returns nil.
  • Token trống, chatID trống hoặc content == nil → log Warn telegram: skip sending document due to invalid parameters, trả nil.
  • Failures: telegram: build request failed / telegram: upload document failed (raw error returned); non-200 → logs telegram: api returned error for document upload and returns telegram api error (status %d): %s.
  • Lỗi: telegram: build request failed / telegram: upload document failed (trả error gốc); khác 200 → log telegram: api returned error for document upload và trả telegram api error (status %d): %s.

funcNewClient
func NewClient(opts Options, httpClient *http.Client, logger *zap.Logger) Client

Never fails and never calls Telegram. A nil httpClient becomes one with a 10s timeout; logger must be non-nil. The token is not validated — a wrong token shows up later as telegram api error (status 401): … (or 404).

Không bao giờ lỗi và không gọi Telegram. httpClient nil được thay bằng client timeout 10s; logger phải khác nil. Token không được kiểm tra — token sai chỉ lộ ra sau đó dưới dạng telegram api error (status 401): … (hoặc 404).

Good to knowCần lưu ý

1"not configured" is not an error"chưa cấu hình" không phải lỗiAn empty token or chat id returns nil. Great for dev, but in production a typo in the env var name means alerts silently never arrive — look for the Warn log line.Token hoặc chat id trống trả về nil. Tiện cho dev, nhưng ở production gõ sai tên biến môi trường nghĩa là cảnh báo âm thầm không bao giờ tới — hãy tìm dòng log Warn.
2escape your HTMLtự escape HTMLNothing is escaped for you. Telegram's HTML mode accepts only a few tags (b, i, code, pre, a…); unknown tags or a bare < / & make it answer 400 and the message is lost.Package không tự động escape HTML cho nội dung. Chế độ HTML của Telegram chỉ hỗ trợ một số thẻ cơ bản (b, i, code, pre, a…); nếu chứa thẻ không hỗ trợ hoặc ký tự <, & chưa escape, Telegram sẽ trả về lỗi 400 và không gửi được tin nhắn.
3the token can reach your logstoken có thể lọt vào logThe token is part of the request URL. On a network failure Go's *url.Error text contains that URL, and the client logs it with zap.Error(err) (and returns it) — so bot<token> can end up in log files.Token nằm trong URL request. Khi lỗi mạng, chuỗi lỗi *url.Error của Go chứa URL đó, và client log nó bằng zap.Error(err) (và trả về) — nên bot<token> có thể nằm trong file log.
4Telegram's own limitsgiới hạn của TelegramThe client does not truncate. Telegram rejects message text longer than 4096 characters and document captions longer than 1024 — you get a 400 telegram api error.Client không cắt ngắn nội dung. Telegram từ chối tin nhắn dài hơn 4096 ký tự và caption tài liệu dài hơn 1024 — bạn nhận lỗi 400 telegram api error.
5no retrieskhông retryOne attempt per call. Retries only happen if the injected *http.Client does them (httpclient.Options.MaxRetries); Jungo's default client has MaxRetries 0.Mỗi request chỉ gửi đúng một lần (không tự retry). Cơ chế retry chỉ hoạt động nếu *http.Client được inject có bật retry (httpclient.Options.MaxRetries); client mặc định của Jungo để MaxRetries = 0.
