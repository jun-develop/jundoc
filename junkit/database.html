type ProductRepository struct {
    db *primary.DB
}

func NewProductRepository(db *primary.DB) *ProductRepository {
    return &ProductRepository{db: db}
}

func (r *ProductRepository) Create(ctx context.Context, input domain.CreateProductInput) (*domain.Product, error) {
    row, err := r.db.Queries(ctx).CreateProduct(ctx, sqlc.CreateProductParams{Name: input.Name})
    if err != nil {
        return nil, wrap("create", database.Match(err, map[database.ErrorType]error{
            database.ErrorUniqueViolation: domain.ErrProductExists,
        }))
    }
    return mapProduct(row), nil
}

func (r *ProductRepository) ListByCategory(ctx context.Context, categoryID int64) ([]productRow, error) {
    rows, err := r.db.Executor(ctx).Query(ctx, `SELECT id, name FROM products WHERE category_id = $1`, categoryID)
    if err != nil {
        return nil, wrap("list by category", err)
    }
    return pgx.CollectRows(rows, pgx.RowToStructByName[productRow])
}

func (r *ProductRepository) WithTransaction(ctx context.Context, fn func(context.Context) error) error {
    return r.db.WithTransaction(ctx, fn)
}

SetupCài đặt

postgres.New builds the pool without connecting; whoever owns it pings on start and closes on stop.

postgres.New dựng pool mà không kết nối; bên sở hữu nó ping khi khởi động và đóng khi dừng.

internal/database/primary/db.go · module.go (shortened)
// One Go type per database, so a repository asking for *primary.DB gets only this one.
type DB struct{ *postgres.DB }

func New(lc fx.Lifecycle, log *zap.Logger, cfg *config.Config) (*DB, error) {
    opts := options(cfg) // Name "primary", DSN and pool settings from cfg.DB
    db, err := postgres.New(opts, log)
    if err != nil {
        return nil, err
    }
    lc.Append(fx.Hook{
        OnStart: func(ctx context.Context) error { return db.Ping(ctx) }, // also logs "postgres: connected"
        OnStop:  func(context.Context) error { db.Close(); return nil },
    })
    return &DB{DB: db}, nil
}

var Module = fx.Module("primary", fx.Provide(New))

Jungo calls postgres.New from its own constructor and registers the ping and close hooks itself, so each database gets its own Go type. How to add a second database: Multiple databases.

Jungo gọi postgres.New từ constructor riêng và tự đăng ký hook ping và đóng, để mỗi database có một kiểu Go riêng. Cách thêm database thứ hai: Nhiều database.

How it worksCách hoạt động

Every query takes the same path.

Mọi query đều đi cùng một đường.

1 · repositoryQueries(ctx) · Executor(ctx)
sqlc or hand-written SQL.
sqlc hoặc SQL viết tay.
2 · pick2 · chọntx in ctx ? tx : pool
Only a transaction begun by this same DB counts.
Chỉ tính transaction do chính DB này mở.
3 · run3 · chạyDecorate → pgx → log
Through the Decorate wrapper (Jungo: the tracer), then pgx, which logs it when QueryLogging is on.
Đi qua wrapper Decorate (Jungo: tracer), rồi pgx, nơi query được log khi bật QueryLogging.
4 · error4 · lỗiMatch(err, map)
PostgreSQL error → ErrorType → domain error.
Lỗi PostgreSQL → ErrorType → lỗi domain.
1

Executor(ctx) is the only way to run a query. There is no accessor for the raw pool, so no query can skip the Decorate wrapper, the log or the transaction.

Executor(ctx) là cách duy nhất để chạy query. Không có hàm lấy pool gốc, nên không query nào đi vòng qua wrapper Decorate, log hay transaction.

2

The transaction travels in ctx, keyed to its DB. WithTransaction puts the tx into txCtx; only that DB's Executor sees it. Another database keeps using its own pool.

Transaction đi trong ctx, gắn với DB của nó. WithTransaction đặt tx vào txCtx; chỉ Executor của DB đó thấy nó. Database khác vẫn dùng pool riêng.

3

Nested calls join; there are no savepoints. WithTransaction on a ctx that already carries the same DB's transaction runs fn in it, and the outer call alone commits or rolls back. An inner Go error that is swallowed still lets the outer one commit; a swallowed SQL error has already aborted the transaction in PostgreSQL, so the outer commit fails. How Jungo uses this across databases: Multiple databases.

Lời gọi lồng nhau nhập vào; không có savepoint. WithTransaction gọi với ctx đã mang transaction của cùng DB sẽ chạy fn trong đó, và chỉ lời gọi ngoài cùng commit hoặc rollback. Nuốt một lỗi Go bên trong thì transaction ngoài vẫn commit; còn lỗi SQL dù bị nuốt thì PostgreSQL đã abort transaction, nên commit bên ngoài sẽ lỗi. Cách Jungo dùng điều này với nhiều database: Nhiều database.

func (d *DB) Executor(ctx context.Context) DBTX
func (d *DB) WithTransaction(ctx context.Context, fn func(context.Context) error) (err error)
func (d *DB) Ping(ctx context.Context) error

  • Executor: this DB's transaction in ctx (decorated), or the
                pre-decorated pool.
    • 
              
  • Executor: transaction của DB này trong ctx (đã decorate), hoặc pool
                đã decorate sẵn.
    • 
              
  • WithTransaction runs fn(txCtx): nil → commit, error →
                rollback and the same error is returned, panic → rollback and re-panic. If ctx already
                carries this DB's transaction, fn(ctx) just runs inside it. A failed begin or commit returns
                postgres: begin transaction: … / postgres: commit transaction: …; a rollback

    •

    •

                closes every pooled connection, waiting for in-use ones.
    •
