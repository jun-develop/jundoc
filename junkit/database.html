database

A PostgreSQL pool whose Executor(ctx) picks up the transaction in ctx by itself — so a repository never has to know whether it runs inside one.

Một pool PostgreSQL có Executor(ctx) tự lấy transaction nằm trong ctx — nên repository không bao giờ phải biết mình có đang chạy trong transaction hay không.

product_repository.go
type ProductRepository struct {
    db *primary.DB
}

func NewProductRepository(db *primary.DB) *ProductRepository {
    return &ProductRepository{db: db}
}

func (r *ProductRepository) Create(ctx context.Context, input domain.CreateProductInput) (*domain.Product, error) {
    row, err := r.db.Queries(ctx).CreateProduct(ctx, sqlc.CreateProductParams{Name: input.Name})
    if err != nil {
        return nil, database.Match(err, map[database.ErrorType]error{
            database.ErrorUniqueViolation: domain.ErrProductExists,
        })
    }
    return mapProduct(row), nil
}

func (r *ProductRepository) ListByCategory(ctx context.Context, categoryID int64) ([]productRow, error) {
    rows, err := r.db.Executor(ctx).Query(ctx, `SELECT id, name FROM products WHERE category_id = $1`, categoryID)
    if err != nil {
        return nil, err
    }
    return pgx.CollectRows(rows, pgx.RowToStructByName[productRow])
}

func (r *ProductRepository) WithTransaction(ctx context.Context, fn func(context.Context) error) error {
    return r.db.WithTransaction(ctx, fn)
}

How it worksCách hoạt động

Every query takes the same path.

Mọi query đều đi cùng một đường.

1 · repositoryQueries(ctx) · Executor(ctx)
sqlc or hand-written SQL.
sqlc hoặc SQL viết tay.
2 · picktx in ctx ? tx : pool
Only a transaction begun by this same DB counts.
Chỉ tính transaction do chính DB này mở.
3 · runtracer → pgx → log
Recorded for the debug dashboard and written to the sql log.
Được ghi lại cho debug dashboard và vào log sql.
4 · errorMatch(err, map)
Postgres error → ErrorType → domain error.
Lỗi Postgres → ErrorType → lỗi domain.
1

Executor(ctx) is the only way to run a query. There is no accessor for the raw pool, so no query can skip the tracer, the log or the transaction.

Executor(ctx) là cách duy nhất để chạy query. Không có hàm lấy pool gốc, nên không query nào đi vòng qua tracer, log hay transaction.

2

The transaction travels in ctx, keyed to its DB. WithTransaction puts the tx into txCtx; only that DB's Executor sees it. Another database keeps using its own pool.

Transaction đi trong ctx, gắn với DB của nó. WithTransaction đặt tx vào txCtx; chỉ Executor của DB đó thấy nó. Database khác vẫn dùng pool riêng.

3

One transaction, one database; nested calls join it. Writes to another database are not part of it. WithTransaction called with a ctx that already carries the same DB's transaction opens nothing new: fn runs in the outer transaction, which alone commits or rolls back. No savepoints: if an inner Go error is swallowed, the outer transaction still commits; a swallowed SQL error has already aborted the transaction in Postgres, so the outer commit fails.

Một transaction, một database; lời gọi lồng nhau nhập vào nó. Lệnh ghi sang database khác không thuộc transaction. WithTransaction gọi với ctx đã mang transaction của cùng DB sẽ không mở gì mới: fn chạy trong transaction bên ngoài, và chỉ transaction đó commit hoặc rollback. Không có savepoint: nếu nuốt một lỗi Go bên trong, transaction ngoài vẫn commit; còn lỗi SQL dù bị nuốt thì Postgres đã abort transaction, nên commit bên ngoài sẽ lỗi.
