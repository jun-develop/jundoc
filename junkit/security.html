Junkit · security

security

Building blocks for authentication: random opaque tokens, sealed (encrypted + signed) for the client and hashed for the database, bcrypt passwords, and a typed identity in the request context.

Các thành phần bảo mật cốt lõi: sinh Opaque Token ngẫu nhiên, niêm phong token (mã hóa AES-256-GCM + ký HMAC-SHA256) gửi cho client, lưu mã băm SHA-256 trong database, băm mật khẩu bằng bcrypt và gắn Identity định kiểu vào context của request.

What it doesNó làm gì

The life of one token. The database only ever sees a hash; the client only ever sees a sealed string. The package has no user or session model — that is your app's job.

Vòng đời an toàn của một token: Database chỉ lưu bản hash SHA-256; client chỉ nhận chuỗi token đã niêm phong. Package không quản lý model user hay session — việc đó do ứng dụng của bạn làm chủ.

Wire it upKết nối

security.Module provides TokenSealer and PasswordHasher. You provide one security.Options. Bad keys or cost stop the app at startup.

security.Module cung cấp TokenSealer và PasswordHasher. Bạn cung cấp một security.Options. Key hoặc cost sai sẽ dừng app ngay lúc khởi động.

internal/app/fx.go
// in CoreModules()
fx.Provide(provideSecurityOptions),
security.Module,

// provideSecurityOptions builds security.Options from cfg.Auth; development falls back
// to random keys.
func provideSecurityOptions(cfg *config.Config, log *zap.Logger) (security.Options, error) {
	opts := security.Options{Password: security.PasswordOptions{Cost: cfg.Auth.PasswordCost}}

	if cfg.IsDevelopment() && cfg.Auth.TokenHMACSecret == "" && cfg.Auth.TokenEncryptionKey == "" {
		log.Warn("security: AUTH_TOKEN_HMAC_SECRET / AUTH_TOKEN_ENCRYPTION_KEY not set, using random keys; tokens will not survive a restart")
		opts.TokenHMACSecret = security.RandomBytes(security.MinHMACSecretSize)
		opts.TokenEncryptionKey = security.RandomBytes(security.EncryptionKeySize)

		return opts, nil
	}

	var err error
	if opts.TokenHMACSecret, err = security.DecodeKey(cfg.Auth.TokenHMACSecret); err != nil {
		return security.Options{}, fmt.Errorf("AUTH_TOKEN_HMAC_SECRET: %w", err)
	}

	if opts.TokenEncryptionKey, err = security.DecodeKey(cfg.Auth.TokenEncryptionKey); err != nil {
		return security.Options{}, fmt.Errorf("AUTH_TOKEN_ENCRYPTION_KEY: %w", err)
	}

	return opts, nil
}

Use it in 30 secondsDùng ngay trong 30 giây

A minimal login + authenticate service. Repo, User and the Err… values are yours. Hover an explanation to light up its lines.

Một service login + xác thực tối giản. Repo, User và các giá trị Err… là của bạn. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

session_service.go
type SessionService struct {
    sealer security.TokenSealer    // from security.Module
    hasher security.PasswordHasher // from security.Module
    repo   Repo
}

func (s *SessionService) Login(ctx context.Context, email, password string) (string, error) {
    user, err := s.repo.UserByEmail(ctx, email) // nil when not found
    if err != nil {
        return "", err
    }
    if user == nil {
        s.hasher.CompareDummy(password) // same time as a real check
        return "", ErrInvalidCredentials
    }
    if !s.hasher.Compare(user.PasswordHash, password) {
        return "", ErrInvalidCredentials
    }

    raw := security.GenerateToken()
    if err := s.repo.SaveTokenHash(ctx, user.ID, security.HashToken(raw)); err != nil {
        return "", err
    }
    return s.sealer.Seal(raw) // v1.<nonce+ciphertext>.<signature>
}

func (s *SessionService) Authenticate(ctx context.Context, token string) (*User, error) {
    raw, err := s.sealer.Open(token)
    if err != nil {
        return nil, ErrInvalidToken // malformed, bad signature or decrypt failure
    }
    return s.repo.UserByTokenHash(ctx, security.HashToken(raw))
}
handler.go
func (h *Handler) Me(c *gin.Context) {
    user := security.MustGetIdentity[*User](c)
    c.JSON(200, user)
}

interfacePasswordHasher

            

              
type PasswordHasher interface {
	Hash(plain string) (string, error)
	Compare(hash, plain string) bool
	CompareDummy(plain string)
}


            

            
    
              
  • Hash — bcrypt hash with the configured cost. Input over 72 bytes →
                ErrPasswordTooLong (no silent truncation).
    • 
              
  • Hash — hash bcrypt với cost đã cấu hình. Đầu vào quá 72 byte →
                ErrPasswordTooLong (không cắt ngầm).
    • 
              
  • Compare — true only if plain matches hash.
                Wrong password, garbage hash or plain over 72 bytes → false (the long case
                still spends one dummy compare).
    • 
              
  • Compare — true chỉ khi plain khớp hash. Sai
                mật khẩu, hash rác hoặc plain quá 72 byte → false (trường hợp quá dài vẫn tốn
                một lần so sánh giả).
    • 
              
  • CompareDummy — compares against a hash made at startup with the same cost, so it
                costs the same time as Compare against hashes made with the current cost. Call it
                when the user does not exist. Hashes stored under an older AUTH_PASSWORD_COST still take a
                different time (nothing rehashes them on login yet), so those accounts stay distinguishable.
    • 
              
  • CompareDummy — so sánh với một hash tạo lúc khởi động với cùng cost, nên tốn đúng
                thời gian như Compare với các hash tạo bằng cost hiện tại. Gọi khi user không tồn
                tại. Hash lưu từ AUTH_PASSWORD_COST cũ vẫn tốn thời gian khác (hiện chưa có bước hash lại
                khi đăng nhập), nên vẫn phân biệt được các tài khoản đó.
    •

              deliberately.Không có key ring. HMAC secret mới → mọi token cũ lỗi
              ErrBadSignature; chỉ đổi encryption key → ErrDecrypt. Hãy chủ động khi đổi

2Dev
                random keysKey ngẫu nhiên khi devIn
              Jungo, development with both keys empty uses random keys: tokens die on every restart. Setting only
              one of the two is a startup error, not a fallback.Trong Jungo, môi trường
              development để trống cả hai key sẽ dùng key ngẫu nhiên: token mất hiệu lực mỗi lần restart. Chỉ đặt

3Never
                store or log raw tokensKhông lưu hay log token gốcPersist HashToken(raw) only. Raw and sealed tokens are both bearer credentials —
              keep them out of logs and error messages.Chỉ lưu
              HashToken(raw). Token gốc và token đã seal đều là bearer credential — đừng để chúng xuất hiện

4HashToken is not for passwordsHashToken không dành cho mật
                khẩuPlain unsalted SHA-256 is fine for 32 random bytes, far too

              không salt ổn cho 32 byte ngẫu nhiên, nhưng quá nhanh với mật khẩu do người đặt. Hãy dùng
              PasswordHasher.

          
572
                bytes, not characters72 byte, không phải 72 ký tựThe bcrypt limit counts UTF-8 bytes: 37 × "é" (74 bytes) already returns
              ErrPasswordTooLong. Validate input length in bytes or map the error to a 422.Giới hạn bcrypt tính theo byte UTF-8: 37 × "é" (74 byte) đã trả
              ErrPasswordTooLong. Hãy kiểm tra độ dài theo byte hoặc chuyển lỗi này thành 422.

          
6Small
                payloads onlyChỉ payload nhỏOpen rejects tokens over 4096 bytes but Seal has no limit: a payload
              over 3008 bytes seals fine and then can never be opened (ErrMalformedToken). Seal IDs /
              random tokens, not documents.Open từ chối token dài hơn 4096
              byte nhưng Seal không giới hạn: payload trên 3008 byte vẫn seal được nhưng không bao giờ open
              được (ErrMalformedToken). Hãy seal ID / token ngẫu nhiên, đừng seal tài liệu.
