upload

Checks an uploaded file — size, extension and the content type sniffed from its first bytes — before you hand it to storage. A .png that is really an HTML page is refused.

What it doesNó làm gì

upload.Open runs three checks in order; the cheap ones first, so an oversized or wrongly named file is never opened or sniffed. Any failed check returns ErrInvalidFile.

upload.Open chạy ba bước kiểm tra theo thứ tự; bước rẻ chạy trước, nên file quá lớn hoặc sai tên không bao giờ bị mở hay đoán kiểu. Bước nào không đạt cũng trả ErrInvalidFile.

Quick startDùng nhanh

An avatar upload handler. Hover an explanation to light up its lines.

Một handler upload avatar. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

avatar_handler.go
var avatarRule = upload.Image(5 << 20) // JPEG, PNG, WebP up to 5 MB

func (h *Handler) UploadAvatar(c *gin.Context) {
    fh, err := c.FormFile("avatar")
    if err != nil {
        h.responder.Send(c, http.StatusBadRequest, "invalid_avatar_file")
        return
    }

    file, err := upload.Open(fh, avatarRule)
    if errors.Is(err, upload.ErrInvalidFile) {
        h.responder.Send(c, http.StatusBadRequest, "invalid_avatar_file")
        return
    }
    if err != nil {
        h.responder.Error(c, err) // I/O failure, not the client's fault
        return
    }
    defer file.Close()

    url, err := h.storage.UploadFile(c.Request.Context(), file, fh.Filename)
    if err != nil {
        h.responder.Error(c, err)
        return
    }

    h.responder.SendWithData(c, http.StatusOK, "avatar_uploaded", gin.H{"url": url})
}

2ErrInvalidFile → 400Too big, wrong extension, or bytes that are not one of Types. Always the same sentinel, so the client learns nothing about which check failed.Quá lớn, sai phần mở rộng, hoặc nội dung không thuộc Types. Luôn cùng một lỗi sentinel, nên client không biết bước nào thất bại.
3Other errors → 500Lỗi khác → 500Failing to open the upload's temp file is a wrapped I/O error (upload: open: …), not ErrInvalidFile.Lỗi mở file tạm của upload là lỗi I/O được bọc (upload: open: …), không phải ErrInvalidFile.

funcOpen
func Open(fh *multipart.FileHeader, rule Rule) (multipart.File, error)
  • Rule violation → ErrInvalidFile (the file is closed for you).
  • Vi phạm Rule → ErrInvalidFile (file được đóng giúp bạn).
  • fh.Open failure → wrapped I/O error.
  • fh.Open lỗi → lỗi I/O được bọc.
  • Success → an open file rewound to the start; the caller closes it.
  • Thành công → file đang mở, đã tua về đầu; người gọi tự đóng.
  • The extension is compared with Extension(fh.Filename), which is lowercase, so upper-case entries in Rule.Extensions never match.
  • Phần mở rộng được so với Extension(fh.Filename) (luôn chữ thường), nên mục viết hoa trong Rule.Extensions không bao giờ khớp.
  • An empty file always fails (nothing to sniff), and so does a file HasType cannot rewind — both as ErrInvalidFile, not as I/O errors.
  • File rỗng luôn bị từ chối (không có gì để đoán kiểu), file mà HasType không tua lại được cũng vậy — cả hai là ErrInvalidFile, không phải lỗi I/O.
funcHasType · Extension
func HasType(file io.ReadSeeker, types ...string) bool
func Extension(filename string) string

HasType sniffs up to 512 bytes, rewinds, and reports whether the type is one of types (an empty file, a read error or a seek error → false). Extension is the lowercased filepath.Ext, dot included ("A.PNG" → ".png").

HasType đọc tối đa 512 byte, tua lại, và báo kiểu có nằm trong types không (file rỗng, lỗi đọc hoặc lỗi seek → false). Extension là filepath.Ext đổi sang chữ thường, có dấu chấm ("A.PNG" → ".png").

Good to knowCần lưu ý

1The body limit stops big uploads, not MaxSizeGiới hạn body chặn upload lớn, không phải MaxSizefh.Size is measured while the whole multipart body is parsed (in memory, then temp files), so by the time Open checks it the bytes are already read. The request body limit is the real cap: in Jungo the global Payload middleware limits every body to SECURITY_MAX_BODY_SIZE (default 2097152 = 2 MiB). For a multipart body it only wraps the body in http.MaxBytesReader and lets the handler run, so the limit trips while the handler parses the form: c.FormFile fails and Jungo answers 400 invalid_avatar_file, not 413. A route that needs more declares it through router.BodyLimited, as the avatar route does; keep that limit and MaxSize in step.fh.Size được đo trong lúc parse toàn bộ body multipart (trong bộ nhớ, rồi ra file tạm), nên khi Open kiểm tra thì byte đã được đọc xong. Giới hạn body của request mới là chốt chặn thật: trong Jungo, middleware Payload toàn cục giới hạn mọi body ở SECURITY_MAX_BODY_SIZE (mặc định 2097152 = 2 MiB). Với body multipart, nó chỉ bọc body bằng http.MaxBytesReader rồi cho handler chạy, nên giới hạn bị vượt trong lúc handler parse form: c.FormFile lỗi và Jungo trả 400 invalid_avatar_file, không phải 413. Route cần lớn hơn thì khai báo qua router.BodyLimited, như route avatar; giữ giới hạn đó và MaxSize khớp nhau.
2Sniffing is not a virus scanĐoán kiểu không phải quét virushttp.DetectContentType only reads magic bytes. It stops renamed HTML or scripts, not a malicious but valid image.http.DetectContentType chỉ đọc magic byte. Nó chặn HTML hay script bị đổi tên, không chặn một ảnh hợp lệ nhưng độc hại.
3Types must match exactlyTypes phải khớp chính xácText types come back with a charset ("text/plain; charset=utf-8"); list that full string in Types.Kiểu text trả về kèm charset ("text/plain; charset=utf-8"); ghi đủ chuỗi đó vào Types.
4Jungo: storage errors become 400Jungo: lỗi storage thành 400UserService.UploadAvatar turns any UploadFile error (e.g. disk full) into ErrInvalidAvatarFile, so a server problem reaches the client as 400 invalid_avatar_file, and the original error is not logged.UserService.UploadAvatar biến mọi lỗi của UploadFile (vd. đầy đĩa) thành ErrInvalidAvatarFile, nên lỗi phía server đến client dưới dạng 400 invalid_avatar_file, và lỗi gốc không được log.
