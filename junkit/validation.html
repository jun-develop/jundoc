validation

Adds extra rules (password_strong, email_advanced, slug…) to gin's binding:"…" tags and turns any binding error into a clean {field: message} map — or a single message — ready for a 422 response.

Thêm các rule mới (password_strong, email_advanced, slug…) cho tag binding:"…" của gin và biến mọi lỗi binding thành map {field: message} gọn gàng — hoặc một message duy nhất — sẵn sàng cho response 422.

What it doesNó làm gì

Two jobs. At startup it registers 11 custom rules on gin's validator. Per request it translates whatever ShouldBind… returned into something a client can show.

Hai việc. Lúc khởi động, nó đăng ký 11 rule tùy chỉnh vào validator của gin. Mỗi request, nó dịch lỗi mà ShouldBind… trả về thành thứ client hiển thị được.

1 · bindctx.ShouldBindJSON(&req)
Gin decodes the body and runs the binding:"…" tags — including the custom rules.
Gin decode body và chạy các tag binding:"…" — gồm cả rule tùy chỉnh.
2 · classifyGetValidationErrors
Type error? Bad number in the query? Rule failed? Broken JSON?
Sai kiểu? Số sai trong query? Rule không đạt? JSON hỏng?
3 · translatei18n key = tag
"required" → "%[1]s is required" → "email is required".
"required" → "%[1]s is required" → "email is required".
4 · respondSendWithData(422, …)
The result becomes "error" in the response envelope.
Kết quả thành "error" trong envelope của response.

Wire it upKết nối

Creating the Validator is what registers the custom rules — do it before the first request.

Chính việc tạo Validator là đăng ký các rule tùy chỉnh — làm trước request đầu tiên.

internal/app/fx.go
// in CoreModules(cfg)
i18n.Module, // provided once, shared with response
// …
fx.Provide(provideValidationOptions),
validation.Module,

// provideValidationOptions returns validation.Options; the zero value uses the built-in
// disposable-email list and a 3s MX timeout.
func provideValidationOptions() validation.Options {
    return validation.Options{}
}

// Messages use the translator's default language:
fx.Invoke(func(t *i18n.Translator) { t.SetDefaultLang(cfg.Language) }),

cfg.Language = env API_LANGUAGE (default en), set once on the shared translator. Fx builds the Validator lazily — in Jungo the handlers ask for *validation.Validator (reached through fx.Invoke(router.RegisterAll)), so it exists before the server starts. If nothing requests it, it is never built, the custom tags are never registered, and the first bind using one panics with Undefined validation function '…' — force it with e.g. fx.Invoke(func(*validation.Validator) {}).

cfg.Language = env API_LANGUAGE (mặc định en), đặt một lần trên translator dùng chung. Fx tạo Validator khi có nơi cần — ở Jungo các handler xin *validation.Validator (thông qua fx.Invoke(router.RegisterAll)), nên nó có trước khi server chạy. Nếu không nơi nào xin, nó không bao giờ được tạo, các tag tùy chỉnh không được đăng ký, và lần bind đầu tiên dùng tag đó sẽ panic với Undefined validation function '…' — hãy ép tạo, ví dụ fx.Invoke(func(*validation.Validator) {}).

type CreateUserRequest struct {
    FirstName   string  `json:"first_name" binding:"required,min=2,max=50"`
    LastName    string  `json:"last_name" binding:"required,min=2,max=50"`
    Email       string  `json:"email" binding:"required,email,email_advanced"`

    PhoneNumber *string `json:"phone_number" binding:"omitempty,phone_advanced"`

user_handler.go
func (h *UserHandler) CreateUser(ctx *gin.Context) {
    var req v1dto.CreateUserRequest
    if err := ctx.ShouldBindJSON(&req); err != nil {
        h.responder.SendWithData(ctx, http.StatusUnprocessableEntity, "validation_error",
            h.validator.GetValidationErrors(ctx, err))
        return
    }
    // req is valid from here on
}

// 1. register on gin's validator (same engine NewValidator uses)
if engine, ok := binding.Validator.Engine().(*validator.Validate); ok {
    err := engine.RegisterValidation("sku", func(fl validator.FieldLevel) bool {
        return strings.HasPrefix(fl.Field().String(), "SKU-")
    })
    if err != nil {
        return err
    }
}

// 2. the message key is the tag name
translator.AddTranslations(map[string]map[string]string{
    i18n.LangEN: {"sku": "%[1]s must start with SKU-"},
})

// 3. use it
type CreateProductRequest struct {
    Code string `json:"code" binding:"required,sku"`
}
// → {"code":"code must start with SKU-"}

funcNewValidator
            

            

              
func NewValidator(opts Options, translator *i18n.Translator) (*Validator, error)

            

            
Loads the blocklist (an error if BlocklistPath can't be read), then, if gin's
              binding.Validator.Engine() is a *validator.Validate (the default), calls
              RegisterCustomValidation on it — a global side effect: the most recently created
              Validator's rules are the ones gin runs. A
              nil translator is allowed: messages then fall back to raw tag names
              ({"name":"required"}), "invalid json syntax" and "invalid request".
            

            
Nạp blocklist (lỗi nếu không đọc được BlocklistPath), rồi nếu
              binding.Validator.Engine() của gin là *validator.Validate (mặc định), gọi
              RegisterCustomValidation lên nó — side effect toàn cục: rule của Validator tạo sau
              cùng là rule gin chạy. Translator
              nil được phép: message khi đó là tên tag thô ({"name":"required"}),
              "invalid json syntax" và "invalid request".

1min / max messages are
              off by oneThe bounds are inclusive but the texts say "longer than" /
              "greater than" / "less than": min=8 accepts 8 characters yet says
              "password must be longer than 8 characters"; max=100 on an int says
              "page_size must be less than 100" although 100 passes. Override the texts if that
              matters.Giới hạn là bao gồm nhưng văn bản lại nói "longer than" /
              "greater than" / "less than": min=8 chấp nhận 8 ký tự nhưng báo
              "password must be longer than 8 characters"; max=100 trên số nguyên báo
              "page_size must be less than 100" dù 100 vẫn đạt. Ghi đè văn bản nếu cần.

          
2email_advanced hits
              DNSA new domain costs a live MX (then A/AAAA) lookup, bounded by
              MXTimeout (3s); answers are cached per Validator for 10 minutes. When DNS itself fails
              (offline, timeout) the address is accepted rather than blocking sign-ups. Nothing is logged.Domain mới tốn một lần tra MX (rồi A/AAAA) thật, giới hạn bởi MXTimeout
              (3s); kết quả được cache theo Validator trong 10 phút. Khi chính DNS lỗi (offline, timeout) địa chỉ được
              chấp nhận thay vì chặn đăng ký. Không log gì.

          
3Keys come from Go
              namesGin's validator reports Go field names, so
              Phone string `json:"tel"` yields the key "phone" for a rule error — but a JSON
              type error on the same field uses "tel". One field, two keys. Keep json tags = snake_case of
              the field name.Validator của gin báo tên field Go, nên
              Phone string `json:"tel"` cho key "phone" khi lỗi rule — nhưng lỗi kiểu JSON
              trên cùng field lại dùng "tel". Một field, hai key. Giữ json tag = snake_case của tên
              field.

          
4Untranslated
              tagsA tag without a catalog entry (e.g. url,
              len, numeric) gives the bare tag as the message. Add a translation for every tag
              you use.Tag không có trong catalog (ví dụ url,
              len, numeric) cho message chỉ là tên tag. Thêm bản dịch cho mọi tag bạn
              dùng.

          
5min_int / max_int are
              integer-onlyThey accept int and uint fields; on a string, float or any
              other kind they simply fail validation (no panic). For floats prefer the standard min /
              max / gte / lte.Chúng nhận field
              int và uint; trên field chuỗi, số thực hay kiểu khác thì chỉ báo không đạt (không panic). Với số thực, nên
              dùng min / max / gte / lte chuẩn.

          
6password_strong
              detailsLength is counted in bytes, and only the listed specials count —
              ~, ` and spaces don't, so "Abcdefg1~" fails.Độ dài tính theo byte, và chỉ các ký tự đặc biệt trong danh sách được tính — ~,
              ` và dấu cách thì không, nên "Abcdefg1~" không đạt.
