validation

Adds extra rules (password_strong, email_advanced, slug…) to gin's binding:"…" tags and turns any binding error into a clean {field: message} map — or a single message — ready for a 422 response.

What it doesNó làm gì

Two jobs. At startup it registers 11 custom rules on gin's validator. Per request it translates whatever ShouldBind… returned into something a client can show.

Hai việc. Lúc khởi động, nó đăng ký 11 rule tùy chỉnh vào validator của gin. Mỗi request, nó dịch lỗi mà ShouldBind… trả về thành thứ client hiển thị được.

1 · bindctx.ShouldBindJSON(&req)
Gin decodes the body and runs the binding:"…" tags — including the custom rules.
Gin decode body và chạy các tag binding:"…" — gồm cả rule tùy chỉnh.
2 · classifyGetValidationErrors
Type error? Bad number in the query? Rule failed? Broken JSON?
Sai kiểu? Số sai trong query? Rule không đạt? JSON hỏng?
3 · translatei18n key = tag
"required" → "%[1]s is required" → "email is required".
"required" → "%[1]s is required" → "email is required".
4 · respondSendWithData(422, …)
The result becomes "error" in the response envelope.
Kết quả thành "error" trong envelope của response.

type CreateUserRequest struct {
    FirstName   string  `json:"first_name" binding:"required,min=2,max=50"`
    LastName    string  `json:"last_name" binding:"required,min=2,max=50"`
    Email       string  `json:"email" binding:"required,email,email_advanced"`
    Password    string  `json:"password" binding:"required,min=8,max=72,password_strong"`
    PhoneNumber *string `json:"phone_number" binding:"omitempty,phone_advanced"`
}
user_handler.go
func (h *UserHandler) CreateUser(ctx *gin.Context) {
    var req v1dto.CreateUserRequest
    if err := ctx.ShouldBindJSON(&req); err != nil {
        h.responder.SendWithData(ctx, http.StatusUnprocessableEntity, "validation_error",
            h.validator.GetValidationErrors(ctx, err))
        return
    }
    // req is valid from here on
}

custom rule

            
// 1. register on gin's validator (same engine NewValidator uses)
if v, ok := binding.Validator.Engine().(*validator.Validate); ok {
    _ = v.RegisterValidation("sku", func(fl validator.FieldLevel) bool {
        return strings.HasPrefix(fl.Field().String(), "SKU-")
    })
}

// 2. the message key is the tag name
translator.AddTranslations(map[string]map[string]string{
    i18n.LangEN: {"sku": "%[1]s must start with SKU-"},
})

// 3. use it
type CreateProductRequest struct {
    Code string `json:"code" binding:"required,sku"`
}
// → {"code":"code must start with SKU-"}

funcNewValidator
            

            

              
func NewValidator(opts Options, translator *i18n.Translator) *Validator

            

            
If gin's binding.Validator.Engine() is a *validator.Validate (the
              default), calls RegisterCustomValidation on it — a global side effect. A
              nil translator is allowed: messages then fall back to raw tag names
              ({"name":"required"}), "invalid json syntax" and "invalid request".
            

            
Nếu binding.Validator.Engine() của gin là *validator.Validate (mặc
              định), gọi RegisterCustomValidation lên nó — side effect toàn cục. Translator
              nil được phép: message khi đó là tên tag thô ({"name":"required"}),
              "invalid json syntax" và "invalid request".

funcRegisterCustomValidation

            

              
func RegisterCustomValidation(v *validator.Validate)

            

            
Loads the default blocklist (creating it from a built-in seed of 100 domains if missing), then
              registers the 11 custom tags on v. Registration errors are only logged
              ("validation: register %s rule: %v"). Use it directly for a standalone
              validator.New() with validate:"…" tags.

            
Nạp blocklist mặc định (tạo từ danh sách seed 100 domain nếu chưa có), rồi đăng ký 11 tag tùy
              chỉnh lên v. Lỗi đăng ký chỉ được log ("validation: register %s rule: %v"). Dùng
              trực tiếp cho một validator.New() riêng với tag validate:"…".

              "page_size must be less than 100" although 100 passes. Override the texts if that
