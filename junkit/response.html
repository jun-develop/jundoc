Junkit · response

response

The only way handlers write HTTP responses: one JSON envelope for every endpoint, translated messages, and domain errors (*AppError) mapped to HTTP status codes.

Chuẩn hóa cách handler trả về HTTP response: định dạng JSON envelope đồng nhất cho mọi endpoint, thông điệp phản hồi đa ngôn ngữ qua i18n, và tự động ánh xạ lỗi nghiệp vụ (*AppError) sang mã HTTP tương ứng.

What it doesNó làm gì

A handler hands over a status code, an i18n key and (maybe) data or an error. The Responder turns that into the same JSON shape every time.

Handler chỉ cần truyền vào status code, i18n message key, cùng dữ liệu (data) hoặc lỗi (error). Responder sẽ chuẩn hóa thành định dạng JSON đồng nhất cho mọi API.

1 · handlerresponder.SendWithData(…)
Or Send, Pagination, Error. Never ctx.JSON directly.
Hoặc Send, Pagination, Error. Không gọi ctx.JSON trực tiếp.
2 · translatei18n.Translator
"user_created" → "User created successfully" in Options.Language.
"user_created" → "User created successfully" theo Options.Language.
3 · enveloperesponse.Response
status, code, message, data / error, plus api_info read from the gin context.
status, code, message, data / error, cộng api_info đọc từ gin context.
4 · JSONctx.JSON(status, …)
2xx/3xx responses with data can be trimmed by response/filter.
Response 2xx/3xx có data có thể được cắt gọn bởi response/filter.

// provideResponseOptions builds response.Options from cfg.
func provideResponseOptions(cfg *config.Config) response.Options {
    return response.Options{Language: cfg.Language}
}

cfg.Language comes from API_LANGUAGE (default en). Any constructor can now ask for response.Responder.

cfg.Language lấy từ API_LANGUAGE (mặc định en). Mọi constructor giờ có thể xin response.Responder.

user_handler.go
func (h *UserHandler) CreateUser(ctx *gin.Context) {
    var req v1dto.CreateUserRequest
    if err := ctx.ShouldBindJSON(&req); err != nil {
        h.responder.SendWithData(ctx, http.StatusUnprocessableEntity, "validation_error",
            h.validator.GetValidationErrors(ctx, err))
        return
    }

    user, err := h.service.CreateUser(ctx.Request.Context(), v1dto.ToCreateUserInput(req))
    if err != nil {
        h.responder.Error(ctx, err)
        return
    }

    h.responder.SendWithData(ctx, http.StatusCreated, "user_created", v1dto.NewUserResponse(user))
}

interfaceResponder
            

            

              
type Responder interface {
    Send(ctx *gin.Context, statusCode int, key string, args ...any)
    SendWithData(ctx *gin.Context, statusCode int, key string, data any, args ...any)
    Pagination(ctx *gin.Context, statusCode int, key string, data any, pagination pagination.Pagination, args ...any)
    Translate(key string, args ...any) string
    Error(ctx *gin.Context, err error)
}


            

            
In every method, key is an i18n key resolved in Options.Language;
              args fill %[1]s-style verbs (only applied if the message contains
              %). Unknown keys are returned unchanged. None of the methods abort the gin chain —
              return after calling them.

            
Ở mọi method, key là i18n key được dịch theo Options.Language;
              args điền vào các verb kiểu %[1]s (chỉ áp dụng khi message có %).
              Key không tồn tại được trả về nguyên văn. Không method nào abort chuỗi gin — hãy return sau
              khi gọi.

1?fields= is off until
              you turn it onThe Responder reads []string from gin keys
              "_response_fields" / "_response_omit", but nothing in Junkit or Jungo sets them.
              Add your own middleware
              (c.Set("_response_fields", strings.Split(c.Query("fields"), ","))).Responder đọc []string từ gin key "_response_fields" /
              "_response_omit", nhưng Junkit và Jungo không chỗ nào đặt chúng. Tự viết middleware
              (c.Set("_response_fields", strings.Split(c.Query("fields"), ","))).

          
2Paths start at the
              envelopeThe filter runs on the whole Response, so paths look
              like data.email or data.items{uuid,email}. In fields-mode only what you list
              survives — fields=data.email also drops status, message and
              api_info. If filtering fails, the unfiltered response is sent.Filter chạy trên toàn bộ Response, nên path có dạng data.email hoặc
              data.items{uuid,email}. Ở chế độ fields chỉ những gì bạn liệt kê còn lại —
              fields=data.email cũng bỏ luôn status, message và
              api_info. Nếu filter lỗi, response gốc được gửi.

          
3Wrapped causes are not
              loggedError only calls ctx.Error(err) for
              non-AppError errors. response.Wrap(response.Internal, "…", dbErr) answers 500
              but the dbErr never reaches the gin error list — log it yourself if you need it.Error chỉ gọi ctx.Error(err) với lỗi không phải
              AppError. response.Wrap(response.Internal, "…", dbErr) trả 500 nhưng
              dbErr không vào danh sách lỗi của gin — tự log nếu cần.

          
4Register every
              keyA key missing from the catalog is sent as the message verbatim
              ("failed_to_save_user"). Add texts with translator.AddTranslations (see i18n).Key không có trong catalog được gửi nguyên
              văn làm message ("failed_to_save_user"). Thêm văn bản bằng
              translator.AddTranslations (xem i18n).

          
5One language per
              processOptions.Language is fixed at startup; there is no
              Accept-Language handling. Only English texts are built in — with "vi", every key
              you haven't translated falls back to English.Options.Language cố định khi khởi động; không xử lý Accept-Language.
              Chỉ có sẵn tiếng Anh — với "vi", key nào bạn chưa dịch sẽ dùng bản tiếng Anh.

          
6Call return
              yourselfThe Responder writes the body but doesn't Abort().
              In middleware, call c.Abort() after it; in handlers, return.Responder ghi body nhưng không Abort(). Trong middleware, gọi
              c.Abort() sau đó; trong handler, return.

          
7Filter ≠ encoding/json
              for embedded structsWhen a filter path walks into a struct, an embedded
              (anonymous) struct without a JSON tag appears as a nested object named after its type instead of being
              flattened like encoding/json does.Khi path filter đi vào một
              struct, struct nhúng (anonymous) không có JSON tag sẽ thành object lồng mang tên kiểu thay vì được trải
              phẳng như encoding/json.
