Your service talks to Cache[T]; Options.Driver decides where values actually live. Code never changes when you switch drivers.

internal/app/fx.go
// in CoreModules(cfg):
fx.Provide(provideCacheOptions),
cache.Module,

// provideCacheOptions selects the Redis driver when enabled, otherwise a no-op cache.
func provideCacheOptions(cfg *config.Config) cache.Options {
    if !cfg.Redis.Enabled {
        return cache.Options{Driver: cache.DriverNoop}
    }

    return cache.Options{
        Driver: cache.DriverRedis,
        Redis: cache.RedisOptions{
            Addr:     cfg.Redis.Host + ":" + cfg.Redis.Port,
            Password: cfg.Redis.Password,
            DB:       cfg.Redis.DB,
        },
    }
}

cache.Module turns the cache.Options in the graph into a cache.Cache[any]. For typed caches, ask Fx for cache.Options and call cache.New[T](opts) yourself — that is what Jungo's features do. cfg.Redis.Enabled is the env var CACHE_ENABLED (default false), so out of the box Jungo runs with the no-op driver.

cache.Module biến cache.Options có trong graph thành một cache.Cache[any]. Muốn cache có kiểu, hãy xin Fx cache.Options rồi tự gọi cache.New[T](opts) — các feature của Jungo làm đúng như vậy. cfg.Redis.Enabled là biến môi trường CACHE_ENABLED (mặc định false), nên mặc định Jungo chạy với driver no-op.

main.go
users := cache.New[*User](cache.Options{
    Driver: cache.DriverRedis,

Use it in 30 secondsDùng ngay trong 30 giây

A service with a typed read-through cache and a fixed-window counter. Hover an explanation to light up its lines.

Một service có cache đọc-xuyên theo kiểu và một bộ đếm theo cửa sổ cố định. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

product_service.go
type ProductService struct {
    repo     domain.ProductRepository
    products cache.Cache[*domain.Product]
    counters cache.Cache[int64]
}

func NewProductService(repo domain.ProductRepository, opts cache.Options) *ProductService {
    return &ProductService{
        repo:     repo,
        products: cache.New[*domain.Product](opts),
        counters: cache.New[int64](opts),
    }
}

func (s *ProductService) Get(ctx context.Context, id uuid.UUID) (*domain.Product, error) {
    return s.products.GetOrSet(ctx, "product:"+id.String(), 5*time.Minute,
        func() (*domain.Product, error) { return s.repo.GetByUUID(ctx, id) })
}

func (s *ProductService) Rename(ctx context.Context, id uuid.UUID, name string) error {
    if err := s.repo.Rename(ctx, id, name); err != nil {
        return err
    }
    return s.products.Delete(ctx, "product:"+id.String()) // next Get reloads
}

// at most 5 exports per user per hour
func (s *ProductService) AllowExport(ctx context.Context, userID string) (bool, error) {
    n, err := s.counters.Incr(ctx, "export:"+userID, time.Hour)
    if err != nil {
        return false, err
    }
    return n <= 5, nil
}

type Cache[T any] interface {
    Get(ctx context.Context, key string) (T, bool)
    Set(ctx context.Context, key string, value T, ttl time.Duration) error
    Delete(ctx context.Context, key string) error
    Exists(ctx context.Context, key string) (bool, error)
    Incr(ctx context.Context, key string, ttl time.Duration) (int64, error)
    GetOrSet(ctx context.Context, key string, ttl time.Duration, fetchFn func() (T, error)) (T, error)
    Close() error
}

  • A Go map behind a sync.RWMutex — safe for concurrent use, local to one process.
              
    • 
              
  • Một map Go sau sync.RWMutex — an toàn khi dùng đồng thời, chỉ trong một
                process.
    • 
              
  • Expired entries are removed lazily by Get, and by a sweep that runs on
                Set / Incr at most once per minute.
    • 
              
  • Entry hết hạn bị xoá lười bởi Get, và bởi một lượt quét chạy trong
                Set / Incr tối đa mỗi phút một lần.
    • 
              
  • Values are stored as-is (no copy): a pointer you get back is the same pointer that is
                cached.
    •

1Zero Options = no
              cachecache.Options{} and typos like
              Driver("Redis") silently give a no-op cache. Counters built on it always return
              0.cache.Options{} và lỗi gõ như Driver("Redis")
              âm thầm cho ra cache no-op. Bộ đếm dựa trên nó luôn trả 0.

          
2Errors look like
              missesIf Redis is down, Get returns a miss and
              GetOrSet keeps calling your loader. Without RedisOptions.Logger (Jungo sets
              none) you will not see it.Khi Redis bị mất kết nối (down),
              Get sẽ coi như cache miss và GetOrSet vẫn tiếp tục gọi loader để lấy dữ liệu từ
              DB. Nếu không cấu hình RedisOptions.Logger (mặc định Jungo không cấu hình), bạn sẽ không nhận
              được log cảnh báo lỗi này.

          
3Memory is per
              processEach replica has its own MemoryCache: counters and
              invalidations are not shared. Use Redis when you run more than one instance.Mỗi replica có MemoryCache riêng: bộ đếm và việc xoá cache không được chia sẻ. Chạy
              nhiều instance thì dùng Redis.

          
4Shared pointers in
              memoryMemoryCache[*T] hands back the cached pointer itself —
              mutating it changes the cache. Copy before modifying (Jungo's session cache does
              session := *entry.Session). Redis always gives you a fresh copy.MemoryCache[*T] trả về chính con trỏ đang được cache — sửa nó là sửa cache. Hãy
              copy trước khi sửa (session cache của Jungo làm session := *entry.Session). Redis luôn trả
              bản copy mới.

          
5nil is a
              valueIf fetchFn returns (nil, nil), the nil is
              cached and later Get reports a hit with a nil pointer. Return an error for "not found"
              instead.Nếu fetchFn trả (nil, nil), nil được
              cache và các lần Get sau báo hit với con trỏ nil. Hãy trả error cho trường hợp "không tìm
              thấy".

          
6No stampede
              protectionConcurrent misses on the same key each call
              fetchFn; there is no singleflight.Nhiều miss đồng thời trên
              cùng key sẽ cùng gọi fetchFn; không có singleflight.

          
7Incr differs slightly
              per driverRedis sets the TTL whenever the key has none (e.g. a key
              earlier Set with ttl 0 gets one on its next Incr) and works in whole
              milliseconds (ttl under 1ms = no expiry). ErrNotInteger exists only in memory; Redis reports
              its own error.Redis đặt TTL bất cứ khi nào key chưa có TTL (vd. key trước
              đó Set với ttl 0 sẽ nhận TTL ở lần Incr tiếp theo) và làm tròn theo mili giây
              (ttl dưới 1ms = không hết hạn). ErrNotInteger chỉ có ở memory; Redis trả lỗi của riêng
              nó.

          
8One pool per
              NewEvery cache.New / NewRedisCache opens its
              own Redis pool (up to 10 × GOMAXPROCS connections), and Fx never calls Close. Jungo opens
              three this way when Redis is on (session cache × 2, login guard × 1).Mỗi
              lần cache.New / NewRedisCache mở một pool Redis riêng (tối đa 10 × GOMAXPROCS
              kết nối), và Fx không bao giờ gọi Close. Khi bật Redis, Jungo mở ba pool như vậy (session
              cache × 2, login guard × 1).

          
9Clear is
              FLUSHDBIt deletes every key in the Redis DB, including other caches and
              other apps sharing it. Prefer DeleteByPattern("product:*").Nó xoá mọi key trong DB Redis, kể cả của cache khác và app khác dùng chung. Nên dùng
              DeleteByPattern("product:*").
