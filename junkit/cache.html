What it doesNó làm gì

Your service talks to Cache[T]; Options.Driver decides where values actually live. Code never changes when you switch drivers.

Service của bạn chỉ làm việc với Cache[T]; Options.Driver quyết định giá trị thực sự nằm ở đâu. Đổi driver không phải sửa code.

Tạo một lần, trên *cache.Store dùng chung. Driver của Store chọn redis, memory hoặc noop (rỗng hoặc lạ → no-op).
2 · readGetOrSet(ctx, key, ttl, fetchFn)

3 · missfetchFn()

SetupCài đặt

With Fx (how Jungo does it) or with the plain constructors.

Dùng Fx (cách Jungo làm) hoặc gọi thẳng constructor.

internal/app/fx.go
// in CoreModules(cfg):
fx.Provide(provideCacheOptions),
cache.Module,

// provideCacheOptions uses Redis when enabled, otherwise no cache, because an in-memory cache
// would let other instances keep serving revoked sessions and permissions.
func provideCacheOptions(cfg *config.Config) cache.Options {
    if !cfg.Redis.Enabled {
        return cache.Options{Driver: cache.DriverNoop}
    }

    return cache.Options{
        Driver: cache.DriverRedis,
        Redis: cache.RedisOptions{
            Addr:     cfg.Redis.Host + ":" + cfg.Redis.Port,
            Password: cfg.Redis.Password,
            DB:       cfg.Redis.DB,
        },
    }
}

cache.Module turns the cache.Options in the graph into one shared *cache.Store (one Redis connection pool for the whole app), closed when the app stops. For typed caches, ask Fx for the *cache.Store and call cache.New[T](s) yourself — that is what Jungo's features do. cfg.Redis.Enabled is the env var CACHE_REDIS_ENABLED (default false), so out of the box Jungo runs with the no-op driver: nothing is cached and every lookup reads the database. Why not memory? Each process would hold its own copy, so with several instances a logout or a removed permission would reach the others only when their copy expires.

cache.Module biến cache.Options có trong graph thành một *cache.Store dùng chung (một pool kết nối Redis cho cả app), được đóng khi app dừng. Muốn cache có kiểu, hãy xin Fx *cache.Store rồi tự gọi cache.New[T](s) — các feature của Jungo làm đúng như vậy. cfg.Redis.Enabled là biến môi trường CACHE_REDIS_ENABLED (mặc định false), nên mặc định Jungo chạy với driver no-op: không cache gì, mọi lần tra đều đọc database. Vì sao không dùng memory? Mỗi process sẽ giữ một bản riêng, nên khi chạy nhiều instance, logout hay một permission bị gỡ chỉ tới các instance khác khi bản của chúng hết hạn.

main.go
s := cache.NewStore(cache.Options{
    Driver: cache.DriverRedis,
    Redis:  cache.RedisOptions{Addr: "localhost:6379"},
})
defer s.Close()

users := cache.New[*User](s)        // every Redis cache shares s's client
counters := cache.New[int64](s)

// or pick a driver directly:
mem := cache.NewMemory[string](cache.MemoryOptions{}) // *Memory[string]
off := cache.NewNoop[*User]()                         // *Noop[*User]
rc := cache.NewRedis[int64](redisClient)              // you own and close redisClient

The concrete constructors return the struct type, so you can reach driver-only methods such as Redis.Ping. NewStore does not wait for a connection: the Redis client connects lazily and never reports background dial errors — call Ping on a Redis cache if you want to fail fast. Close the Store once, after every cache on it is done.

Các constructor cụ thể trả về kiểu struct, nên bạn dùng được method riêng của driver như Redis.Ping. NewStore không chờ kết nối: client Redis kết nối lười và không báo lỗi dial ở nền — gọi Ping trên một Redis cache nếu muốn phát hiện lỗi sớm. Gọi Close trên Store một lần, sau khi mọi cache trên nó đã xong.

Quick startDùng nhanh

A service with a typed read-through cache and a fixed-window counter. Hover an explanation to light up its lines.

Một service có cache đọc-xuyên theo kiểu và một bộ đếm theo cửa sổ cố định. Rê chuột vào giải thích để làm sáng các dòng tương ứng.

product_service.go
type ProductService struct {
    repo     domain.ProductRepository
    products cache.Cache[*domain.Product]
    counters cache.Cache[int64]
}

func NewProductService(repo domain.ProductRepository, s *cache.Store) *ProductService {
    return &ProductService{
        repo:     repo,
        products: cache.New[*domain.Product](s),
        counters: cache.New[int64](s),
    }
}

func (s *ProductService) Get(ctx context.Context, id uuid.UUID) (*domain.Product, error) {
    return s.products.GetOrSet(ctx, "product:"+id.String(), 5*time.Minute,
        func() (*domain.Product, error) { return s.repo.GetByUUID(ctx, id) })
}

func (s *ProductService) Rename(ctx context.Context, id uuid.UUID, name string) error {
    if err := s.repo.Rename(ctx, id, name); err != nil {
        return err
    }
    return s.products.Delete(ctx, "product:"+id.String()) // next Get reloads
}

// at most 5 exports per user per hour
func (s *ProductService) AllowExport(ctx context.Context, userID string) (bool, error) {
    n, err := s.counters.Incr(ctx, "export:"+userID, time.Hour)
    if err != nil {
        return false, err
    }
    return n <= 5, nil
}

typeStorefuncNewStore · OrMemory · Close

            

              
type Store struct { /* unexported */ }

func NewStore(opts Options) *Store
func (s *Store) OrMemory() *Store
func (s *Store) Close() error


            

            
The shared storage caches are built on: one lazily connecting Redis client per app, or none for
              the memory and no-op drivers. Close releases the Redis client; caches built on the Store
              must not be used afterwards.

            
Kho dùng chung mà các cache được dựng trên đó: một client Redis kết nối lười cho cả app, hoặc
              không có gì với driver memory và no-op. Close giải phóng client Redis; các cache dựng trên
              Store không được dùng sau đó nữa.

            
OrMemory returns the Store itself when it uses Redis; otherwise a memory
              Store. Use it
              for counters and blocks that must work without Redis (a no-op cache would never block), accepting that
              each instance then keeps its own. Jungo's login guard and middleware.Banner use it.

            
OrMemory trả về chính Store khi nó dùng Redis; ngược lại trả một Store memory. Dùng cho bộ
              đếm và lệnh chặn phải chạy được cả khi không có Redis (cache no-op sẽ không bao giờ chặn), chấp nhận mỗi
              instance giữ bản riêng. Bộ chặn login của Jungo và middleware.Banner dùng nó.

          


          

            
typeInvalidatable[T]invalidatable.go

            

              
func NewInvalidatable[T any](s *Store, ttl time.Duration) *Invalidatable[T]

func (c *Invalidatable[T]) GetOrLoad(ctx context.Context, key string,
    markers func(T) []string, load func() (T, error)) (value T, hit bool, err error)
func (c *Invalidatable[T]) Delete(ctx context.Context, key string) error
func (c *Invalidatable[T]) Invalidate(ctx context.Context, marker string) error


            

            
A cache for values that must be dropped before their TTL when the data behind them
              changes — Jungo's sessions (markers: the family and the user) and permissions (markers: the user and a global
              one).

            
Cache cho những giá trị phải bỏ trước khi hết TTL khi dữ liệu gốc thay đổi — session của
              Jungo (marker: family và user) và permission (marker: user và một marker chung).

            
    
              
  • Invalidate stores the current time under marker, kept for 2× TTL
                (a slow load can write its entry after it).
    • 
              
  • Invalidate lưu thời điểm hiện tại dưới marker, giữ trong 2× TTL
                (một lần nạp chậm có thể ghi entry sau đó).
    • 
              
  • GetOrLoad stores each entry with the time its load started. An entry is
                a miss when one of markers(value) was set after that time, or within 2 s before it (clock
                skew between instances). So a load that read the old data and finished after the change is never
                served. A marker that cannot be read counts as invalidated, so a backend error never serves revoked data. hit tells whether the value came from the cache.
    • 
              
  • GetOrLoad lưu mỗi entry kèm thời điểm bắt đầu nạp. Entry bị coi là miss
                khi một trong markers(value) được đặt sau thời điểm đó, hoặc trong vòng 2 giây trước đó
                (lệch đồng hồ giữa các instance). Nhờ vậy một lần nạp đọc dữ liệu cũ mà xong sau khi dữ liệu đổi sẽ
                không bao giờ được trả ra. Marker không đọc được thì coi như đã vô hiệu hoá, nên lỗi backend không bao giờ trả ra dữ liệu đã bị thu hồi. hit cho biết giá trị lấy từ cache hay không.
    • 
              
  • Delete drops one entry so the next GetOrLoad loads it. A load still
                running can write the old value back; call Invalidate too when that matters.
    • 
              
  • Delete xoá một entry để lần GetOrLoad sau nạp lại. Một lần nạp đang
                chạy có thể ghi lại giá trị cũ; hãy gọi thêm Invalidate khi điều đó quan trọng.
    • 
              
  • With a memory backend the cached value is shared: copy it before changing it. A failed load
                is not cached. ttl <= 0 always loads.
    • 
              
  • Với backend memory, giá trị cache được dùng chung: hãy copy trước khi sửa. Lần nạp lỗi không
                được cache. ttl <= 0 thì luôn nạp lại.
    •

typeRedis[T]funcNewRedis

            

              
type Redis[T any] struct { /* unexported */ }

func NewRedis[T any](client *redis.Client) *Redis[T]

// implements Cache[T]; one extra method:
func (c *Redis[T]) Ping(ctx context.Context) error


            

            
Does not own its client: the caller (usually the Store) closes it.
              Values are stored as JSON (encoding/json), so T must round-trip through JSON:
              only exported struct fields survive, and in a Redis[any] numbers come back as
              float64 and objects as map[string]any. Errors are wrapped as
              cache: <op>: …; the package never logs.

func NewMemory[T any](opts MemoryOptions) *Memory[T] // implements Cache[T]


            

            
    
              
  • A Go map behind a sync.RWMutex — safe for concurrent use, local to one process.
                A Get that finds an expired entry re-checks it under the write lock before deleting, so a
                concurrent Set / Incr is never lost.
    • 
              
  • Một map Go sau sync.RWMutex — an toàn khi dùng đồng thời, chỉ trong một
                process. Get gặp entry hết hạn sẽ kiểm tra lại dưới write lock trước khi xoá, nên một
                Set / Incr chạy đồng thời không bao giờ bị mất.
    • 
              
  • Expired entries are removed lazily by Get, and by a sweep that runs on
                Set / Incr at most once per minute. At most MaxEntries (default
                100,000) entries: storing a new key in a full cache evicts an arbitrary one (map order, not LRU).
    • 
              
  • Entry hết hạn bị xoá lười bởi Get, và bởi một lượt quét chạy trong
                Set / Incr tối đa mỗi phút một lần. Tối đa MaxEntries (mặc định
                100.000) entry: lưu key mới vào cache đầy sẽ loại một key bất kỳ (theo thứ tự map, không phải LRU).
    • 
              
  • Values are stored as-is (no copy): a pointer you get back is the same pointer that is
                cached.
    • 
              
  • Giá trị được lưu nguyên (không copy): con trỏ bạn nhận về chính là con trỏ đang nằm trong
                cache.
    •
